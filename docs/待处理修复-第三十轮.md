# 第三十轮：抽屉文件按实际文件名显示 + 点下载不跳页

用户 2026-10-14 两张截图提了两件事：

> ①「已安装 mod 里面多组文件的名称一致，无法区分，要根据实际的文件名显示」
> ②「浏览 mod 的时候点击下载不切换到下载页面，直接后台加入下载，只在当前 mod 上显示状态」

本轮没有需要追问的口径 —— 两条诉求都指向明确，直接改。

---

## 一、需求 ①：抽屉里的文件行显示**磁盘实际文件名**

### 现场（截图里的样子）

抽屉「已安装的文件（2 个，可逐个操作）」下面两行：

```
Captain EVE (CNS compatible)   已启用
Pak 模组 · v1.01 · 文件 10808 · 125.4 MB · 2025-10-12 01:49

Captain EVE (CNS compatible)   已启用
Pak 模组 · v1.01 · 文件 10808 · 126.4 MB · 2025-10-11 01:40
```

名字一样、版本一样、文件 ID 一样 —— 只有大小和时间不同，用户只能靠猜。

### 根因

不是抽屉渲染写错了，是**显示名在主进程就被覆盖了**。

`src/main/scanner.js:60-75`，pak 组产出 installed 项时：

```js
const reg = registry.byTarget(target) || registry.get('disk:paks:' + g.key);
return {
  name: reg && reg.name ? reg.name : g.name,   // ← 这里
  files: g.files,                              // ← 实际文件名在这里
  ...
};
```

同一个 Mod 装了两份时：

1. 磁盘上两个 pak 文件**基名不同** → `scanPaks()` 分成**两个 pak 组**（`g.key` 不同）；
2. 两组都有注册表记录（都通过 Nexus 装过）→ 两个 `reg.name` 都是**同一个 Nexus Mod 名**；
3. `groupInstalled()` 又按 `meta.modId` 把两组并进同一个 Mod 组 → 抽屉里出现两行 `it.name` 相同的条目。

**实际文件名一直没丢**，就在 `it.files[].name` 里（如 `Captain EVE (CNS compatible).pak`）——
只是渲染时没用它。

### 修法

`src/renderer/app.js` 新增 `installedFileName(it)`（放在 `installedFilesHtml()` 之前）：

```js
const FILE_AUX_EXT = /\.(ucas|utoc)$/i;

function installedFileName(it) {
  if (!it) return '';
  if (it.kind === 'prereq') return it.name || '';       // 前置组件保留可读名
  const files = ((it.files) || []).filter(f => f && f.name);
  if (!files.length) return it.name || '';
  const bare = f => String(f.name).replace(/\.disabled$/i, '');
  const main = files.find(f => /\.pak$/i.test(bare(f)))
    || files.find(f => !FILE_AUX_EXT.test(bare(f)))
    || files[0];
  return bare(main).replace(/\/+$/, '');
}
```

挑选顺序与几条口径：

| 场景 | 结果 | 为什么 |
|---|---|---|
| pak 组（`X.pak` + `X.ucas` + `X.utoc`） | `X.pak` | `.ucas` / `.utoc` 是索引，不是本体 |
| 文件在目录里乱序 | 仍是 `X.pak` | 靠**扩展名**挑，不靠 `readdirSync` 的返回顺序 |
| 禁用状态（`X.pak.disabled`） | `X.pak` | ⚠️ 必须先剥 `.disabled` 再判扩展名 —— 否则 `.pak$` 匹配不上，反而可能挑中 `X.ucas.disabled` |
| 只有附属文件 | 第一个 | 宁可显示 `.ucas` 也不返回空 |
| script mod（`BpModLoader/`） | `BpModLoader` | 去掉结尾斜杠 |
| 前置组件（UE4SS / CNS） | `UE4SS` | `files` 里是 `dwmapi.dll`、`ue4ss/` 这种零件名，显示出来没人看得懂 |
| 没有 `files` | 回退 `it.name` | 老数据 / 异常条目不至于空白 |

`installedFilesHtml()` 里把 `it.name` 换成 `installedFileName(it)`：

```js
const shown = installedFileName(it);
...
<div class="fli-name" data-i18n-skip title="${esc(shown)}">${esc(shown)} ${st}</div>
```

> `data-i18n-skip` 保留 —— 文件名是**运行时数据**，不能进词表（进了会污染 13 个语言包）。

**没有新增任何用户可见文案**，i18n 无需改动。

## 二、需求 ②：点下载不跳页，状态只落在卡片上

### 现状

`dlEnqueue()` 里无条件切页：

```js
await refreshDownloads();
switchPage('p-download');     // ← 一律跳走
```

所以用户在浏览列表里每点一次下载就被拽到下载页一次。

### 修法

给 `dlEnqueue()` 加一个 `goto` 开关（默认 `true`，老调用方零改动）：

```js
async function dlEnqueue(meta, { authorize = true, goto = true } = {}) {
  ...
  await refreshDownloads();
  if (goto) switchPage('p-download');
  else scheduleCardStateRefresh();
  ...
}
```

两处**浏览页入口**改成 `{ goto: false }`：

| 入口 | 位置 |
|---|---|
| 卡片上的「⬇ 下载」（`data-dl-add`） | `app.js` 点击处理里 `await dlEnqueue(meta, { goto: false })` |
| 抽屉里文件列表每行的「⬇ 下载」（`data-dl-file`） | 同一个处理块，多行对象后面追加 `, { goto: false }` |

**仍然跳转的三处**（故意保留）：

| 入口 | 为什么不改 |
|---|---|
| 批量下载（`batchDownload()`） | 一次下十几个，用户本来就想看整队进度 |
| `nxm://` 外部入口 | 用户是在 Nexus 网页上点的下载，界面得让他看到任务真的动起来了 |
| 安装 UE4SS（`installUe4ss()`） | 前置组件安装，用户期待看到进度 |

### 为什么卡片能**立刻**亮起来

`goto:false` 时调的是 `scheduleCardStateRefresh()`（400ms 节流版）→ `refreshCardStates()`
→ 查 `nexus.localState(ids)` 拿每个 Mod 的本地状态 → 只替换**状态真的变了**的卡片。

能立刻拿到「下载中」，是因为 `src/main/localState.js` 的任务状态映射把**入队后的每一个中间态**
都算作下载中：

```js
awaiting_authorization: 'downloading',
queued: 'downloading',
resolving: 'downloading',
downloading: 'downloading',
```

于是点完下载，卡片封面角标变「● 下载中」、按钮变「查看进度」—— 用户想细看时**自己点**那个按钮。
`scheduleCardStateRefresh()` 还会顺带刷新**开着的抽屉**（`applyDrawerLocalState`），
所以在抽屉里点下载，抽屉里的状态行也会跟着更新。

## 三、测试

`npm run test:all` → **36 个套件 / 2242 断言 / 0 失败**（上一版 2217）。

| 套件 | 断言 | 变化 |
|---|---|---|
| `test:installed-merge` | 100（原 86） | 新增 `[6]` 章：`installedFileName()` 抽真身跑 14 条 —— 直接复现用户截图现场（**同一个 Nexus 名下的两个文件，渲染出来的名字必须不同**），外加 `.pak` 优先、`.disabled` 剥离、script 目录名、前置组件保留可读名、空值不抛 |
| `test:batch-download` | 65（原 54） | 新增 `[3]` 章 11 条：`goto` 开关存在、`goto:false` 时不是「什么都不做」、「**两处**浏览页入口都改了」（只改一处会漏掉抽屉那条路）、批量与 `nxm://` 仍跳转、以及「入队即是 downloading」的状态映射 |

两条最容易改漏的边界都被钉住了：

- **只改一处入口** —— 抽屉里文件列表那颗下载按钮是另一个 `data-dl-file` 分支，
  很容易只改卡片忘了它；断言直接数 `goto: false` 的出现次数必须等于 2。
- **状态映射** —— 就算加了 `goto:false`，如果 `localState.js` 不把 `queued` 算作
  `downloading`，卡片也不会有任何反应（用户会以为点了没用）。这条单独一个断言。
