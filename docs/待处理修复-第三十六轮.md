# 第三十六轮：ATOOL 装好之后不显示「已安装」

用户 2026-10-14 报（截图标题栏 `v0.2.8-dev（开发模式）`）：

> 「**Atool 这个mod 安装好后，不显示已安装；**」

Nexus mod **1662「Animation Tool (ATOOL)」**，落点 `SB\Content\Paks\LogicMods\`。

---

## 一、先确认「是没装上」还是「没认出来」

现场取证（`D:\games\Star Blade`）：

```
SB\Content\Paks\LogicMods\HD-ATOOL_P\HD-ATOOL_P.pak
SB\Content\Paks\LogicMods\HD-ATOOL_P\HD-ATOOL_P.ucas
SB\Content\Paks\LogicMods\HD-ATOOL_P\HD-ATOOL_P.utoc     ← 三件套齐全
```

`data/mods.json`（开发模式的真现场，不是 `%APPDATA%` 那份）里
`source.modId === 1662` 有 **2 条**记录，都是 `kind: "logicmod"`、`enabled: true`、
`manifest` 三项路径全部指向上面那三个文件。

**结论：文件装对了、注册表也写了，是「已安装」的判定链路没认它。**

### 判定链路

```
scanner.scan(root, registry)   ← 唯一来源
        ↓  scanned[].meta.source.modId
localState.buildLocalIndex()   ← installed Map
        ↓
浏览页卡片上的「已安装」角标
```

`localState.js` 顶部注释写得很清楚：**「用 scanner 结果而不是原始注册表 —— 这样
『文件已被手动删掉』的注册表条目不会误报成已安装」**。方向没错，问题出在 scanner
那一头。

### scanner 的 6 步里，没有一步会主动扫 `LogicMods\`

| 步 | 扫什么 | 能覆盖 ATOOL 吗 |
|---|---|---|
| ① | UE4SS 本体 | ✗ |
| ② | **CNS** —— 只认 `DekCNS_P.pak` + `DekCNS\Scripts\main.lua` 两个特征 | ✗ |
| ③ | `~Mods\` 的 pak | ✗（LogicMods 与 ~Mods 是两套目录） |
| ④ | `ue4ss\Mods\` 脚本目录 | ✗ |
| ⑤ | **注册表兜底** —— manifest 里至少一个文件真实存在 | ← **唯一通路** |
| ⑥ | 给①–⑤补原始安装包信息 | —— |

第 ⑤ 步的第一道过滤把 ATOOL 挡掉了：

```js
// 旧代码
const prereqModIds = new Set(prereqs.all().filter(p => p.modId).map(p => Number(p.modId)));
for (const reg of registry.all()) {
  if (seen.has(reg.id)) continue;
  if (/^builtin:/.test(reg.id)) continue;
  if (reg.source && prereqModIds.has(Number(reg.source.modId))) continue;   // ← 就是这一行
  …
}
```

`prereqs.all()` 里装着 `ue4ss` / `cns` / **`atool`**（`modId: 1662`）——
这个过滤的**本意**是「别让已经由①/②步代表过的前置组件在列表里出现第二条」，
但它写成了**无条件**跳过。而①/②步只代表 UE4SS 和 CNS，**ATOOL 没有任何一步代表它**：

```
                 ┌─ ① UE4SS 分支：不认 ATOOL
ATOOL 的通路 →   ├─ ② CNS 分支：不认 ATOOL
                 └─ ⑤ 注册表兜底：被 prereqModIds 跳过  ✗
```

**被两头排除 ⇒ 永远进不了 `scanned` ⇒ 永远进不了 installed Map ⇒ 卡片一直显示「未安装」。**

用真实 runner 坐实（`.workbuddy/tmp/scan-probe.js`，修复前）：

```
scan() 返回条数: 441
结果里 modId=1662 的条数: 0          ← 一条都没有
注册表里 modId=1662 的条数: 2
   nexus:1662:12836 → 出现在 scan 结果里? false
   nexus:1662:12834 → 出现在 scan 结果里? false
kind 分布: {"prereq":2,"pak":421,"script":10,"cns":8}
out 里 logicmod 条数: 0
```

## 二、为什么这套测试没拦住它

`_probe/atool-test.js` 第二十九轮就写好了，**83 条断言**，覆盖四层：

1. `game.layout()` 的 `logicModsDir`
2. `game.atoolStatus()` —— 按特征文件判定（平铺 / 内层两种落点）
3. `prereqs` 的 atool 条目
4. `installer.analyze()` 的落点与依赖标记

**但 `package.json` 里根本没有 `test:atool`，它也不在 `test:all` 的链上。**
它是一个游离在 `_probe/` 里的脚本，只有人手动跑才会跑。

而且就算跑了，那四层也**测不到这个 bug** —— 前四层全绿，用户照样看到「未安装」，
因为漏掉的正好是**判定链条上最关键的一环**：

> 前四层测的是「ATOOL 的落点规则对不对 / 特征文件认不认」；
> 这个 bug 出在「扫描结果里有没有它」。

**没测到那一环，就等于没测。**

## 三、修法

### 1. 前置组件不再「一概跳过」，改成按事实判断（`src/main/scanner.js`）

```js
// 已经出现在 out 里的前置组件 modId（例如第 2) 步的 CNS）—— 它们不必再列一条
const representedPrereqs = new Set(
  out.filter(m => m.meta && m.meta.source)
    .map(m => Number(m.meta.source.modId))
    .filter(id => id > 0)
);
…
if (reg.source && prereqModIds.has(Number(reg.source.modId))
  && representedPrereqs.has(Number(reg.source.modId))) continue;
```

语义从「**它是**前置组件就跳过」变成「**它已经被别的分支代表过**才跳过」。
-CNS 走②步入 `out` → `representedPrereqs` 含 1496 → 照旧跳过（行为不变）；
-ATOOL 谁也不代表 → 不跳过 → 走原有的「manifest 至少一个文件存在」门槛 → 入列表。

`representedPrereqs` 必须在循环**之前**算好（基于①–④步的 `out`）。

### 2. 同一 modId 的多条注册记录：只留最近装的那条（同一处）

修好①之后暴露出第二个问题：**注册表里那 2 条 1662 记录都会入列表** ——
列表里会冒出两个一模一样的「Animation Tool (ATOOL)」。

这两条的 `manifest` 指向**同一组落点文件**（作者更新后 fileId 变了，新版本覆盖了旧版本，
但两条注册记录都在）。按「modId + 落点签名」去重：

```js
const claimedTarget = new Map();          // `${modId}|${落点签名}` → 已 push 的注册表记录
…
const modId = reg.source && reg.source.modId != null ? Number(reg.source.modId) : 0;
if (modId > 0) {
  const sig = modId + '|' + entries.map(f => String(f.path).toLowerCase()).sort().join('|');
  const prev = claimedTarget.get(sig);
  if (prev) {
    if (String(reg.installedAt || '') <= String(prev.installedAt || '')) continue;
    const at = out.findIndex(m => m.id === prev.id);   // 新的一条更晚 → 摘掉旧的那条
    if (at >= 0) out.splice(at, 1);
  }
  claimedTarget.set(sig, reg);
}
```

`installedAt` 是 ISO 字符串，字典序比较等价于时间序。**两条都没时间戳时保守留第一条。**

⚠️ **只对「同一 modId」去重**。不同 mod 共用同一组 pak 文件名是真实存在的
（`minervha_master_P.pak/ucas/utoc` 被 4 个 mod 2759/2359/2705/2241 同时登记，
见 `registry.byTargetAll` 的注释）——那些**必须各列一条**，否则界面上就分不清
文件到底属于谁了。签名里带上 modId 就是为了把它们分开。

### 3. 修完的实测（`.workbuddy/tmp/local-probe.js`）

## 四、测试

`npm run test:all`（权威汇总用 `node _probe/_run-all.js`，`npm run test:all` 本身只顺序跑、不汇总）
→ **38 个套件 / 2589 断言 / 0 失败**（基线 37 套 / 2490 断言，差额 = atool 99，逐项吻合）。

### 1. `atool-test.js`：补第 5 层（83 → 99 断言）

新增第 9) 节，用**独立的临时游戏根 + 临时注册表**（不复用文件前面那个 ROOT ——
它已经被前面的用例塞过东西，状态不干净），钉死 16 条：

| 断言 | 盯的是什么 |
|---|---|
| 扫描结果里有 ATOOL（旧代码返回 0 条） | 这个 bug 本身 |
| 条目 id / kind / 落点 / fileCount / meta | 第⑤步入列表后的字段完整性 |
| **localState 把 1662 认成「已安装」** | 用户看到的那一步 |
| **浏览页卡片能挂上 local 状态** | 同上，端到端 |
| 两条注册记录只出一条 / 留 12834 | 去重 |
| 顺序颠倒仍只出一条 / 仍是 12834 | 按 installedAt 判新旧，不靠注册表出厂顺序 |
| LogicMods 里文件被删光 → 不出现 | 第⑤步原有的 `alive` 门槛没被破坏 |
| 不同 modId 共用同一组文件 → 各列一条 | 去重不许误伤 |
| CNS 仍然只出一条 | 放宽前置跳过之后没产生重复 |

**回归防线有效性已验证**：把第 5) 步改回旧逻辑跑一遍 → 13 条转红；改回来 → 99 全绿。

### 2. `package.json`：`test:atool` 接进 `test:all`

第二十九轮写好之后它一直是游离的（不在 `test:all` 里），这是 bug 能漏到用户手里的
**直接原因**。现在 `test:all` 是 **38 个套件**（原 37 + atool），位置在 `test:cns` 之后
（两个框架的自检相邻）。

7-Zip 是既有依赖（`installer-test` / `pickdir-test` / `variant-cover-test` /
`installer-deps-test` 都在用它造测试包且都已接进 `test:all`），所以没有新增环境要求。

### 3. 写断言时踩到的坑：**空数组会静默通过**

第一版是这么写的：

```js
t('条目 id 沿用注册表的 id', () => mine[0] && mine[0].id === 'nexus:1662:12834' ? true : mine[0] && mine[0].id);
```

`mine` 为空数组时 `mine[0]` 是 `undefined` → 整个表达式求值为 `undefined` →
而 `t()` 把 `undefined` 当通过（它的约定是「返回 true 或 undefined 即通过」）。

于是**最该失败的那个场景（ATOOL 一条都没扫出来）反而全绿** ——
把旧逻辑放回去复验时只有 6 条转红，这几条静默通过，一眼看过去还以为防线没问题。

改法：**一律先 `|| {}` 取默认对象再判字段**。

```js
const A = mine[0] || {};
t('条目 id 沿用注册表的 id', () => A.id === 'nexus:1662:12834' ? true : String(A.id));
```

改完再复验：旧逻辑下 **13 条全红**，失败信息是 `→ undefined`（而不是无声通过）。

> 同类坑：`e && e.registryId === x ? true : JSON.stringify(e)`（`idx.installed.get()` 可能为空）、
> `bMine[0] && …`。凡是「数组/Map 可能查不到」的地方，都要先落成默认值。

## 五、遗留

1. **用户手动把 ATOOL 拖进 `LogicMods\`（注册表里没记录）仍然不会显示「已安装」。**
   第 5) 步是「注册表驱动」的，这是它的既有边界。要覆盖这一半，得仿照②步给 ATOOL
   加一个**特征文件分支**（`game.atoolStatus()` 已经具备全部判定能力：
   `installed` / `layoutKind` / `coreFound`），push 一条 `id: 'builtin:atool'`、
   `kind: 'prereq'` 的条目。本轮没做 —— 用户报的是管理器安装的场景，
   而新增 `builtin:*` 条目会牵扯卸载按钮对 builtin id 的处理，风险面比收益大，
   留待用户确认是否要。

2. 作者更新 ATOOL 后 **`fileId` 会变**（`prereqs.js` 里固定写 12834）。
   这不影响一键安装（注入脚本高亮不到时会退化成高亮所有下载按钮），
   但会让「主文件」判定漂。属 CNS 同款已知项。

3. 本轮只修了「显示」。`installer.js` 的落点规则（第二十九轮做的）本来就是对的 ——
   实测 `LogicMods\HD-ATOOL_P\` 三件套齐、与 `~Mods\HD-ATOOL-expr1-slot23_P.*`
   （动画包，**该**落 ~Mods）并存，落点分工正确。
