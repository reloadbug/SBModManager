# 第三十五轮：抽屉内容顺序 / 对比框补全 / 同组文件只出一个对比入口

用户 2026-10-14 三张截图、三句话：

> ① 「mod详细信息中，文件信息，操作按钮都放到顶部，尽量不滚动就能点，图片依然在最顶端，然后说文件信息」
> ② 「目前对比的功能显示不完整」
> ③ 「这3个文件是一组mod，只显示一个对比框即可，信息里面罗列3个文件即可，是两个mod对比，其实主要是比较截图」

三件事互相独立，逐个说。

---

## 一、浏览页 Mod 详情抽屉：图片 → 文件 → 操作按钮

### 1. 口径

用户原话的顺序很明确：**图片依然在最顶端，然后说文件信息**；文件信息与操作按钮
**尽量不滚动就能点**。

所以 `openNexusDrawer()` 的 `#dBody` 重排成：

```
图集（hero 大图）
文件          ← 文件列表
[操作按钮行]  ← #dActions
说明          ← 中文 / English 切换 + 正文
来源
信息          ← 本地状态 / Mod ID / 作者 / 版本 / 分类 / 下载量 / 点赞 / 时间
```

「看过一次就不用再看」的元数据（来源 / 信息）一律往下排，把高频动作顶上来。

### 2. 操作按钮从底部固定栏搬进内容区

原来是 `#dFoot`（底部固定栏，`flex:none`），要滚到底才看得见。「下载主文件」是
这个页面**最高频**的动作，放那儿不合理。现在四颗按钮挂在内容区的 `#dActions`：

```js
$('#dFoot').innerHTML = '';                       // 这个抽屉不用底部栏
$('#dActions').innerHTML = `
  <button class="btn" data-openurl="…">在浏览器打开</button>
  <button class="btn" data-gallery="…">刷新图集</button>
  <button class="btn" data-install="…">手动安装</button>
  <button class="btn p" data-dl-add="…">⬇ 加入下载队列</button>
`;
```

配套三处**必须一起改**，否则按钮会「时有时无」：

| 位置 | 改法 |
|---|---|
| `applyDrawerLocalState()` | `const foot = state.drawer.kind === 'nexus' ? $('#dActions') : $('#dFoot');` —— 按钮容器**按抽屉类型分** |
| `renderFiles()` | `document.querySelector('#dActions [data-dl-add], #dFoot [data-dl-add]')` —— 跨两个容器找那颗「加入下载队列」 |
| `style.css` | `.dfoot:empty{display:none}` —— 空的底部栏别再占一条高度 |

**另外两个抽屉（已安装详情 / 下载详情）完全没动**，仍在 `#dFoot`。
`#dActions` 是浏览页详情独有的。

### 3. 文件列表封顶高度

多文件 Mod（`.pak` / `.ucas` / `.utoc` 各一版，再加几个可选文件）能列十几行，
不封顶就会把下面的操作按钮顶出屏幕 —— 「尽量不滚动就能点」直接落空。

```css
.nxfiles{max-height:240px;overflow:auto;padding-right:4px}
```

### 4. `applyDrawerLocalState` 覆盖 `#dActions` 的行为**与改前一致**

这条容易被误判成回归：已安装的 Mod 打开详情时，`#dActions` 会被改写成
「在浏览器打开 + 去已安装页查看」两颗，原来的「手动安装 / 加入下载队列」消失。

**这是改前就有的行为**（当时覆盖的是 `#dFoot`），本轮只是换了容器，语义一字未变。
未安装（`st` 为 null）时函数提前 `return`，四颗按钮原样保留。

## 二、覆盖对比框右侧「要装进去（新）」整块是空的

### 1. 根因：拿不到「要装进去那份」的 meta

```js
// 改前
const st = state.modalTask || {};
const meta = state.cmpIncoming || st.meta || {};
```

- `state.modalTask` 存的是**任务 id 字符串**（`'dl-1739…'`），不是任务对象 ——
  `.meta` 永远是 `undefined`；
- `state.cmpIncoming` 是**死变量**，全文从未被赋值过。

两条岔路都断 → `meta` 恒为 `{}` → 右侧显示 `Mod #?` / `版本 —` / `作者 —` /
「没有封面图」。用户看到的就是这个（截图 #2）。

### 2. 修法：显式传参，不再事后猜 state

新增模块级 `cmpIncomingMeta`，由调用方在**渲染冲突清单那一刻**写入 ——
那一刻上下文是明确的：

```js
function conflictListHtml(d, opts = {}) {
  if (opts.incoming) cmpIncomingMeta = opts.incoming;
  …
}
```

两个调用点各自传自己那份：

| 调用点 | 传什么 |
|---|---|
| 下载详情抽屉 | `conflictListHtml(cd, { incoming: meta })`（`meta = t.meta`） |
| 手动安装确认抽屉 | `conflictListHtml(p.conflictDetails, { incoming: st.meta || {} })` |

### 3. 左栏也一并补全

原来左栏只有「名字 + Mod ID + 文件清单」。`installFlow.js` 的 `owners` 里其实早就带了
`version` / `author` / `pictureUrl`（当初为对比功能加的），只是渲染层没用上。
现在 `tgtMap` 顺手收集，按钮上挂 `data-cmp-ver` / `-author` / `-pic`，
点击时传进 `openCmpModal(oldModId, oldName, oldInfo)`：

```js
<div id="cmpOldFace">${faceOf(oldInfo.pictureUrl || '')}</div>
<div class="cmp-name">…</div>
${kv('Mod ID', '#' + oldModId)}
${kv('版本', verText(oldInfo.version))}
${kv('作者', oldInfo.author)}
```

**两栏第一帧就是完整的**，不用等图集拉回来。

### 4. 「其实主要是比较截图」

两侧都**主动拉图集**：左栏按已装 modId 拉，右栏 meta 里没图时按新 modId 拉
（走同一条本地缓存，拉过一次就是瞬时）。只给一张封面不够比。

### 5. 顺手清掉两个脏东西

- `meta.__oldCover`（旧方案残留，恒为 `''`）；
- `if (faceBox && !document.getElementById('modal').classList.contains('on') === false)`
  —— `!x === false` 等价于 `!!x`，**恒真**，看着像校验其实什么都没校验。改成显式取值。
- `<div class="cmpwrap cmpwrap">` 重复类名。

## 三、同一组 mod 的多个文件只出一个对比入口

### 1. 口径

一组 mod 的 3 个文件（ATOOL 那种 `.pak` / `.ucas` / `.utoc`）原来**每行各挂一个
一模一样的「对比」按钮** —— 3 行 3 个按钮，点哪个都是同一个对比框。

改成：

- **按目标 modId 去重**，在清单**顶部**出一个入口（`.cfl-cmpbar`）；
- 按钮上标出这个入口覆盖了**几个文件**（`（3 个文件）`）；
- **行内不再放对比按钮**，只留「定位」；
- 「这 3 个文件」的罗列还在原来的行里（用户：「信息里面罗列 3 个文件即可」）。

多个不同目标时按目标各出一个（一个目标一个按钮，不是一堆）。

`.cfl-cmpbar` 用了 `position:sticky;top:0` —— 清单自身 `max-height:300px` 会滚，
粘住顶部才不至于滚两下入口就跑没影（同一个「尽量不滚动就能点」的诉求）。

### 2. ⚠️ 按钮文案必须拆成**三个文本节点**

i18n 是**按文本节点整串查表**的（见 `src/renderer/i18n.js`）。第一版我写成一句：

```js
`⇄ 与「${label}」对比${g.n > 1 ? `（${g.n} 个文件）` : ''}`
```

中文界面没问题，**非中文界面会整句留在中文**：

- ① 整串查表 → 字典里没有这条（名字是动态的）；
- ② 剥噪声后再整串 → 词核心里有「与 / 对比」，不是 `⇄ 对比`；
- ③ 长片段子串替换 → 会换掉一部分，但**验收标准是「结果里不能有汉字」**，
  剩下的 `与「X」对比` 一票否决 → 整句回滚。

所以拆成三个 span：

```html
<span>⇄ 对比</span>                                    <!-- 整串命中字典 -->
<span data-i18n-skip>「Mod 名」</span>                 <!-- 动态数据，豁免 -->
<span>（3 个文件）</span>                              <!-- 靠已有的「个文件」片段剥数字翻 -->
```

实测（`_probe/i18n-lookup-test.js` 钉住）：`⇄ 对比` → `⇄ Compare` / `⇄ 比較` / `⇄ Сравнить`；
`（3 个文件）` → `（3 files）` / `（3 個のファイル）`。**没有新增任何一个 i18n 键。**

## 四、测试

基线来自 `_probe/_run-all-result.json`（0.2.8）。

| 套件 | 断言 | 说明 |
|---|---|---|
| `test:conflicts` | 70 → **99**（+29） | 新增 [8] 段：入口去重、`cmpIncomingMeta` 写入、`state.modalTask` / `state.cmpIncoming` 不再被读、左栏字段、抽屉顺序、CSS |
| `test:drawer-mask` | 45 → **57**（+12） | `conflictListHtml` 跑真身：3 个文件只出 1 个入口、button 开合仍是 4 对、两个目标两个入口、`opts.incoming` 落到 `cmpIncomingMeta` |
| `test:i18n-lookup` | 351 → **390**（+39） | 3 条新用例 × 13 种语言 = 39，专拦「把三个 span 拼回一句」 |
| 合计 | 2410 → **2490** | 37 个套件 / 0 失败 |

### 三处「测试本身」的坑

1. **`desc-default-test.js` 的窗口太窄**：`/state\.drawer\.mod = m;[\s\S]{0,800}descBoxHtml\(state\.drawer\)/`
   —— `#dBody` 模板变长后（多铺了文件列表与按钮行）距离从 <800 涨到 1246，断言转红。
   这条要保的是**先后顺序**（先落 state 再渲染），改成 1600 并写清楚为什么。
2. **`file-download-test.js` 的假 DOM 选择器写死了**：
   `sel === '#dFoot [data-dl-add]'` —— 现在是 `'#dActions [data-dl-add], #dFoot [data-dl-add]'`。
   假 DOM 必须与真代码**一字不差**，已同步。
3. **`conflict-detail-test.js` 里 `state.modalTask` 全文黑名单是错的**：
   它在别处（`dlReveal` / 弹窗「打开文件夹」）是**正当用法**，只是不该被对比框读。
   断言要**限定在函数体内**。抽函数体时又踩了老坑：`app.js` 是 **CRLF**，
   `indexOf('\n}\n')` 匹配不上 → 切片一路吞到文件末尾 → 假失败。先归一成 LF 再切。

### `_probe/drawer-mask-test.js` 的沙箱也要补声明

`conflictListHtml` 抽真身进 vm 时，`cmpIncomingMeta` 是 `app.js` 的**模块级 `let`**，
不会跟过来。第一版靠 sloppy 模式的隐式全局「能跑」，但语义已经漂了；
现在显式补 `let cmpIncomingMeta = {};` 并暴露一个 `getIncoming()` 取值器。
`clip()` 也得一并 `extract()` 进去（按钮文案要用它截断长 Mod 名）。

## 五、遗留

- **对比框左栏的「文件清单」仍是文本行**（`f.rel || f.name` 用 `<br>` 拼），
  没有右侧那样按文件分组高亮。用户这次没提，先不动。
- **右侧的版本 / 作者仍来自 `meta`**（下载任务或安装计划里那份），
  与 `owners` 走的是不同来源。极少数情况下（任务 meta 缺字段）右侧仍可能是 `—`；
  真要彻底解决得在 `openCmpModal` 里按 `meta.modId` 反查一次 Nexus 详情，
  目前只在**图集**上做了这件事（用户「主要是比较截图」）。
- **仓库根目录那张未跟踪散图** `5e34eb9cdb51c7b03f398c31b48dc617.jpg` 仍在，
  已问过多次，用户未表态，未处理。
- **ATOOL（mod 1662）支持**仍是调研状态（`docs/ATOOL-调研与支持方案.md`），
  硬需求是给 `installer.js` 的 `STRUCTURAL` / `structuralRules()` 补 `logicmods`。
