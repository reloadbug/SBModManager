# 筛选区 UI 改版设计（0.9.0）

> 起因：用户 2026-11-23 反馈「红框区域显示不正确、筛选区域按钮要对齐排放均匀、要有合理布局；
> 整体 UI 优化，先整理当前功能逻辑再设计新界面；要满足之前的全部逻辑，但分区更清晰简洁；
> 排序按钮要支持正反排序，不要正反排序弄两个按钮」。
> 本文只讲设计，经用户确认后才动代码。

---

## 一、当前逻辑盘点（改版要一条不落地保住）

### 1. 状态（单选，9 档）

| chip | 含义 | 备注 |
|---|---|---|
| 全部 | 所有记录（在线 + 已下载 + 已安装） | 不显示数字 |
| 未下载 | Nexus 上有、本地没有安装包也没装过；**点它走在线浏览（Nexus 分页）** | 不显示数字（背后是整站 3000+） |
| 已下载 | 安装包在管理器里、还没装进游戏 | |
| 已安装 | 装进游戏（含已启用 / 已禁用） | |
| 已启用 | 装进游戏且开关是开的 | |
| 已禁用 | 装进游戏但开关关着 | |
| 部分启用 | 一个 Mod 里只有部分文件被关掉 | |
| 未登记 | 没有 Nexus Mod ID，认不出是哪个 Mod | |
| 已关联 | 手动关联到了 Nexus 条目 | |

- 数字口径：`libFilterRecords(recs, { skip: 'status' })` —— 其它条件都算上，写多少就筛出多少（0.8.4）。
- 互斥：单选，再点一次回到「全部」以外的同级？现状是单选切换。

### 2. 标记（四颗，各自三态）

| chip | 极性 | 三态顺序 | 默认 |
|---|---|---|---|
| 👍 喜欢 | 正 | 全部 → 只看 → 排除 → 全部 | 全部 |
| 👎 不感兴趣 | 负 | 全部 → 排除 → 只看 → 全部 | **排除** |
| ⚠ 有 bug | 负 | 全部 → 排除 → 只看 → 全部 | **排除** |
| ✓ 已验证 | 正 | 全部 → 只看 → 排除 → 全部 | 全部 |

- 数字：该标记的命中数（排除 N = 排掉 N 个）。chip 文字顺序是「状态词 + 数字 + 标签」（0.7.6）。
- 「不感兴趣」同时是黑名单：默认隐藏（`blockMode='hide'`），切到「只看」时显示。

### 3. 信息（两小组）

- **分类**：单选 chips + 计数（Nexus 分类，本地档案可能是英文 value、显示中文 `categoryZh`）。
  选中后 `state.lib.catSet=true`；「清除筛选」把它复位。在线档的旧分类值不带进合并档（0.5.5 的 `catSet` 语义）。
- **成人**：三档单选 —— 隐藏成人 / 全部内容 / 只看成人。

### 4. 排序（现状：8 颗按钮，两排互斥）

- 在线四档：下载最多 / 最多点赞 / 最新发布 / 最近更新（走 Nexus 接口，方向由接口固定）。
- 本地四档：开启时间 ↓ / 开启时间 ↑ / 安装时间 ↓ / 名称。
- 两排互斥：点在线档会把 `state.lib.sort` 清空，点本地档会把在线 chip 的 `.on` 去掉。

### 5. 操作（12 颗，多数只在多选态出现）

- 常驻：多选。
- 多选态：全选、批量下载、批量安装、批量启用、批量禁用、批量卸载；批量标记 🌐喜欢/不喜欢/有 bug/已验证/未验证；在线档还有「加载更多」。
- 批量按钮带条数（`下载（3）`），执行中按钮显示进度（`禁用 3/12`），结束后轻量刷新。

### 6. 其它

- 顶部搜索框（顶栏）参与筛选，关键词对合并档就地筛。
- 统计行：`共 N 个 Mod · 已安装 X · 已下载 Y · 未下载 Z（筛选自 M 个）`。
- 筛选条件持久化：`lastFilters.lib = { status, marks{四颗}, sort, catSet }`，每次变化 `saveFilters()`。

## 二、实测到的布局问题（这次要修的就是这些）

用装机版量了 `#browseHead` 里每个元素（窗口 1348×781，2026-11-23）：

| 问题 | 实测数字 |
|---|---|
| 状态行 / 标记行**没有左列标签格**（两个 `.slabel` 被塞在 `.grp` 里），与下面几行第一颗 chip 的 x 对不上 | 状态第一颗 chip x=276，排序第一颗 x=277（差 1px 但标签列宽度不同）；状态/标记两行的标签是内嵌的 |

| 成人三档被顶到最右边，与分类之间空出 ~300px | 成人 x=1081，分类最后一颗结束于 1073 |
| 排序 8 颗按钮，同一维度占两颗（↓ 一颗、↑ 一颗） | 排序行宽 585px，`开启时间 ↓` + `开启时间 ↑` 各 77px |
| 操作行在非多选态只剩「多选」一颗，却仍占一整行（24px + 上下间距） | 操作行 h=24，11 颗 `display:none` |
| chip 宽度不一（45 / 56 / 67 / 79 / 99 / 122 px），不构成网格 | 状态行 9 颗宽度 45~79 |
| 吸顶区整体偏高 | `headH = 219px`（窗口高 781 时占 28%） |

## 三、新布局（5 行 → 4 行，全部同一条 40px 标签列）

```
┌─ 吸顶区（sticky）────────────────────────────────────────────────────────────┐
│ 状态   [全部][未下载][已下载][已安装][已启用][已禁用][部分启用][未登记][已关联]  │
│ 标记   [全部 1 👍喜欢][排除 2 👎不感兴趣][排除 3 ⚠有bug][全部 120 ✓已验证]      │
│ 分类   [全部][服装][杂项][视觉][玩法][界面][…]  │ 成人 [隐藏成人][全部][只看成人] │
│ 排序   [下载最多][最多点赞][最新发布][最近更新][开启时间][安装时间][名称] [↓]   │
│ 操作   （多选态才出现）[全选][批量下载][安装][启用][禁用][卸载] ｜ [👍][👎][⚠][✓] │
│ ─────────────────────────────────────────────────────────────────────────── │
│ 共 301 个 Mod · 已安装 301 · 已下载 0 · 未下载 0            多选 ▸            │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1. 对齐规则（硬规则，写进 CSS）

- 每一行 = `.sect{display:grid;grid-template-columns:40px 1fr;column-gap:9px;align-items:center}`。
  左列 `.slabel{text-align:right;color:var(--dim2);font-size:11px;letter-spacing:.5px}`。
- **所有行第一颗 chip 的 x 必须相同**（本次目标：都在 x=277，即左列 40px + 9px gap 之后）。
- 同一行 chip 统一规格：`height:24px; border-radius:7px; font-size:11.5px; padding:0 10px`，
  且 `min-width:84px; justify-content:center`（数字长短不同也等宽，形成网格）；
  分类这种「名字长度差别大」的一组用 `grid-auto-columns:minmax(84px,max-content)`。
- 允许换行（`flex-wrap:wrap`），但**不横向滚动**（滚动的代价是藏按钮）。换行后仍与左列对齐。
- 分区之间用 1px 上边框（`.sect + .sect{border-top:1px solid var(--border);padding-top:5px}`），
  不再靠留白暗示分组。

### 2. 状态行

- 9 颗保持单选、等宽、左对齐；「未下载」不显示数字（沿用 0.8.5 的结论）。
- 超宽时换行（第二行仍从 x=277 起）。

### 3. 标记行

- 4 颗保持三态；文字仍是「状态词 + 数字 + 标签」，宽度按最长那颗（`👎 不感兴趣`）统一到 122px，
  4 颗等宽；排除态用红色描边（`.ex`），只看态用实心（`.on`）。
- 行尾加一颗小号「重置筛选」（把所有状态/标记/分类/成人/关键词复位），原来散在筛选行末尾的「清除筛选」并到这颗。

### 4. 分类行（原「信息」行）

- 左列标签写 **分类**（撤掉原来那颗空的 40px 占位）。
- 分类 chips 与成人三档**同一行、同一基线**：分类一组，紧跟一个竖线分隔符，再「成人」小标签 + 三颗。
- 分类多于 12 个时，第 12 颗之后出现「更多 ▾」，点开展成第二行（只影响这一行高度）。

### 5. 排序行（**核心改动：方向只用一颗按钮**）

- 维度 chips（7 颗单选，等宽 84px）：
  `下载最多` / `最多点赞` / `最新发布` / `最近更新` / `开启时间` / `安装时间` / `名称`
- 方向按钮 1 颗，紧跟在维度 chips 后面：
  - 显示当前方向：`↓`（降序，从新到旧 / 从多到少）或 `↑`（升序）。
  - 点它 = 只翻转方向，不换维度。
  - 点已激活的维度 chip = 翻转方向；点别的维度 = 换维度 + 用该维度的默认方向。
- 默认方向：时间类（最新发布 / 最近更新 / 开启时间 / 安装时间）默认 `↓`；数量类（下载最多 / 最多点赞）默认 `↓`；名称默认 `↑`（A→Z）。
- **在线四档没有升序接口**（Nexus 只给降序语义）：选中在线四档时方向按钮置为 `↓` 并置灰，
  `title` 写「Nexus 的排序只有从多到少 / 从新到旧，本地排序才能翻转」。
- 数据结构改动：
  ```js
  state.lib.sortBy = 'downloads'   // downloads|endorsements|newest|updated|on|installed|name
  state.lib.sortDir = 'desc'       // desc|asc
  ```
  存档迁移：`on-desc→on+desc`、`on-asc→on+asc`、`inst-desc→installed+desc`、`name→name+asc`、
  以及旧的在线四档值 → `sortBy=值, sortDir='desc'`。旧存档读不出来就回默认（`downloads+desc`）。

### 6. 操作行（非多选态不占高度）

- **非多选态**：整行不渲染；「多选」按钮移到统计行右侧（`共 … 个 Mod            多选 ▸`）。
- **多选态**：操作行出现，内容按「会做几件事」分三段，用竖线分隔：
  `全选 ｜ 批量下载 · 安装 · 启用 · 禁用 · 卸载 ｜ 👍 不喜欢 ⚠ 已验证`，
  每颗带条数，执行中显示进度；行尾保留「加载更多」（仅在线档）。
- 进入多选态时吸顶区高度会增加一行 —— 这是用户主动进入的模式，接受了。

## 五、不改的东西（明确保住）

- 状态九档语义、数字口径（`skip` 自己的维度）、「未下载」走在线浏览、chip 不写数字。
- 标记四颗的三态语义、默认「排除」负面标记、黑名单默认隐藏。
- 分类单选 + `catSet` 语义、成人三档、筛选条件持久化（`saveFilters()` 每个入口照挂）。
- 批量操作的全部行为：只对 has modId 的生效、按状态亮灰、进度、结束后轻量刷新。
- 排序字段本身（含「开启时间」用于排查新装 Mod）、缺值沉底、无排序记录不参与排序。
- 搜索框位置（顶栏）与就地筛。

## 六、实施步骤（确认后执行）

1. `index.html`：按 §3 重排 `#browseHead`（5 行结构、真标签、排序加方向按钮、操作行收进多选态）。
2. `style.css`：`.sect` 改 grid 两列 + 等宽 chip 规则 + 分区上边框；删掉旧的 `.grp/.sline` 特例。
3. `app.js`：
   - `state.lib.sort` → `sortBy/sortDir`，`LIB_SORTS` 改维度表（含默认方向），`applyLibSort` 按方向排；
   - `paintLibHead` 重写（状态/标记/分类/成人/排序 分组渲染 + 方向按钮态）；
   - `libFilterSnapshot` / `applyLastFilters` 加迁移；
   - 「多选」按钮移到统计行、`selUpdateBar` 同步显隐。
4. 探针：`libmerge`（布局断言换成新结构）、`enabletime`（排序改 sortBy/sortDir）、`filters`（存档迁移）、`blacklist`/`favorites`（窗口）。
5. 真机量尺寸（每行第一颗 chip x、headH、有无溢出）→ 截图 → 版本 0.9.0 → 打包安装。
