## 一、3 条「有 3 个文件会被覆盖」—— 其实是**同一个共用底座**

| Mod | 界面说 | 真相 |
|---|---|---|
| 2121 Kaine - CNS | 有 3 个文件会被覆盖 | 覆盖的是**共用底座** |
| 2531 S Bikini - CNS | 有 3 个文件会被覆盖 | 同上 |
| 1917 D.Va OG suit - CNS | 有 3 个文件会被覆盖 | 同上 |

三条报的是**同一批文件**：

```
Minervha_Master_P.pak
Minervha_Master_P.ucas
Minervha_Master_P.utoc
```

把归档里和游戏目录里的对出来比：

| 文件 | 归档内 | 游戏目录里 |
|---|---|---|
| `Minervha_Master_P.pak` | 339 | 339 |
| `Minervha_Master_P.ucas` | 100743776 | 100743776 |
| `Minervha_Master_P.utoc` | 20140 | 20140 |

**逐字节同大小。** Minervha 系的 CNS 服装 mod **每一个都自带同一个底座**，
所以装第二个及以后必然命中这 3 个文件 —— 而正确动作显然是**覆盖它**
（社区里 Vortex / MO2 就是这么装的）。这根本不是冲突，是被判据误伤。

### 修法：同名 + 同大小 = 「软冲突」

```js
const st = fs.statSync(m.to);
if (m.size && st.size === m.size) { softConflicts.push(m); return false; }  // 不算冲突
```

- 同一个文件**大小必然相同**；不同版本**几乎不可能刚好一样大**。
- 软冲突**照旧走覆盖前备份**，卸载还能还原 —— 所以「宁可少打扰一次」是安全的取舍。
- 返回体带 `softOverwriteCount` / `softOverwritePaths`，日志里也能看到，
  排查「装完没变化」时一眼就知道「包里带的是和游戏里一模一样的底座」。

## 二、4 条「需要选一套」—— 确实要选，但**已经替你选好了**

437 / 1378 / 2595 / 1430 是**真·变体包**（同款不同配色/款式，互斥），必须你来定。
但老对话框进来是「**一个都没选**」，你得自己判断「哪几套会互相覆盖」——
而这件事程序**本来就算得出来**。

### 修法：按互斥组默认预选

打开对话框时：

- **互斥组**（标着 `第 N 组 · 只能选一套`）→ 每组预选第一套；
  点同组另一套会**自动换过去**（组内单选，不会让你选重）。
- **不在任何组里的**（互不相关的几套）→ **全部预选**。

实测效果：

| Mod | 候选 | 默认预选 |
|---|---|---|
| 1430 BP Cooling suit | 7 套配色 | 1 套 |
| 1378 Eve Iberis Dress | 2 套 | 1 套 |
| 2595 School Uniform | 2 套 | 1 套 |
| 437 BP Planet Diving Suit | 9 套 | **3 套**（A + V2_A + V3_A，三组各一套） |
| 692 Eve BP Nude | 7 套 | 3 套 |
| 3970 Nv_pu_CNS | 3 套互不相关 | **3 套全选** |

**互斥判据**：两个候选含**同一份资产**（资产 ID 相同；没有资产编号的包退化成
「pak 文件名相同」）。这条判据与「选完之后真正装的时候」的撞车检测
**是同一套代码**，不会出现「界面说可以一起装、装的时候又报覆盖」。
