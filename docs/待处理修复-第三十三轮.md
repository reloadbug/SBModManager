# 第三十三轮：记住上次的筛选条件

用户 2026-10-14 截图追加：

> 「设置里面增加一个选项，保存最后一次的筛选条件，不用每次都重新赛选；已安装的mod也是同样道理；」

截图是**设置页**，诉求拆成两半：

1. 设置里加一个开关 —— 记住上次的筛选条件；
2. 浏览页和「已安装 Mod」页**都要**（不是只做浏览页）。

## 一、口径：记什么、不记什么

| | 记 | 不记 |
|---|---|---|
| 浏览页 | 排序、成人内容范围、只看未安装、黑名单模式、只看喜欢、分类、标签 | **搜索关键词**、滚动位置、加载了多少页 |
| 已安装页 | 排序、是否显示 UE4SS 内置脚本 | 详情抽屉开没开 |

**搜索词为什么不记**：那是临时查询。下次打开还留着上次的关键词，用户会以为列表坏了
（「怎么只有 3 个 mod？」）。滚动位置同理 —— 翻到一半的位置没有回忆价值。

## 二、实现

### 1. 快照：一个纯函数

```js
function browseFilterSnapshot(b) {
  const s = b || state.browse;
  return {
    sort: s.sort,
    adultMode: s.adultMode,
    onlyUninstalled: !!s.onlyUninstalled,
    blockMode: s.blockMode,
    onlyLiked: !!s.onlyLiked,
    category: s.category || '',
    tags: Array.isArray(s.tags) ? s.tags.slice() : []   // 副本，改快照不污染 state
  };
}
```

落盘结构（写进 `config.lastFilters`）：

```json
{
  "browse": { "sort": "newest", "adultMode": "hide", "onlyUninstalled": true,
              "blockMode": "hide", "onlyLiked": false, "category": "Outfits", "tags": ["CNS"] },
  "installedSort": "time",
  "showBuiltin": false
}
```

### 2. 保存：只挂一处钩子

浏览页有 8 个筛选入口（排序 / 成人内容 / 只看未安装 / 黑名单 / 只看喜欢 / 分类 / 标签 / 搜索），
但**全都收敛在 `loadBrowse(true)`** —— 所以只在它的 reset 分支尾加一行：

```js
if (reset) {
  …
  saveFilters();   // 所有筛选入口最终都走这里
}
```

已安装页的排序与内置脚本开关各挂一处（它们不走 `loadBrowse`）。

`saveFilters()` 是 **350ms 防抖** 的：连点几个标签只落盘一次，不会把配置写十遍。

### 3. 恢复：只做一次

```js
// refreshAll() 里
if (!filtersApplied) {
  filtersApplied = true;
  const before = JSON.stringify(browseFilterSnapshot());
  applyLastFilters();
  syncBrowseFilterUI();
  filtersReady = true;
  if (before !== JSON.stringify(browseFilterSnapshot())) loadBrowse(true);
}
```

三个要点：

- **`filtersApplied` 守卫**：`refreshAll()` 会被反复调用（手动刷新按钮、装完 Mod、改完目录…）。
  每次都重套的话，用户刚把排序改成「最新」、随手点一下刷新 —— 筛选被顶回上次存的值，
  这比没这功能还糟。
- **放在 `renderInstalled()` 之前**：`refreshAll` 里紧接着会画已安装页，
  恢复得早一步，那一趟就直接按恢复后的排序与开关画，不用画两遍。
- **变了才重拉**：首屏 `switchPage('p-browse')` 可能已经用默认筛选拉过一轮了。
  比较恢复前后快照，真变了才 `loadBrowse(true)`（否则白跑一趟接口）。
  重拉本身是安全的 —— `loadBrowse` 有**代际令牌**，新的 reset 会抢占还在飞的那一轮。

### 4. 启动闸门 `filtersReady`（**这轮最关键的坑**）

首屏流程是：

```
main() → switchPage('p-browse') → loadBrowse(true) → saveFilters()   ← 此时 state 还是默认值！
       → refreshAll() → 才拿到 config.lastFilters → 恢复
```

`saveFilters` 有 350ms 防抖，恢复通常在几十毫秒内就跑完了 —— 看起来「恢复在前、落盘在后」，
顺序没问题。但**这个顺序不由我们决定**：

- `loadBrowse(true)` 排队的那一刻，state 还是**默认值**；
- 定时器到点时读的是**当时的 state**；
- 恢复跑没跑完、快还是慢，取决于 bootstrap（要跑 `inspectGame` + `listMods` +
  `nexusAuth.getStatus`，还带一次磁盘对齐）。

只要 bootstrap 稍慢，定时器到点时 state 仍是默认值 → **默认值落盘，上次存的筛选永久丢失**。
更糟的是它不是稳定复现 —— 「有时管用、有时失效」的 bug 最难查。

所以加一道闸门：

```js
function saveFilters() {
  if (!filtersReady) return;   // 启动恢复完成前，一个字都不许写
  …
}
```

恢复完成后才 `filtersReady = true`。测试里专门钉死这条（「启动恢复完成前不落盘」）。

### 5. 只认合法值

```js
if (BROWSE_SORT_VALUES.includes(bf.sort)) b.sort = bf.sort;   // 非法 → 退回默认
if (ADULT_MODES.includes(bf.adultMode)) b.adultMode = bf.adultMode;
if (BLOCK_MODES.includes(bf.blockMode)) b.blockMode = bf.blockMode;
b.tags = Array.isArray(bf.tags) ? bf.tags.filter(x => typeof x === 'string') : [];
b.category = typeof bf.category === 'string' ? bf.category : '';
```

配置文件是明文 JSON，用户可能手工改、旧版本可能存了别的取值、以后某个取值也可能改名。
**宁可比用户少恢复一项，也不能把界面搞成一个空列表** —— 排序值非法时若无脑塞进去，
请求直接报错或者列表空掉，用户会以为 mod 全没了。

`showBuiltin` 只认布尔（`typeof === 'boolean'`），传 `"yes"` 不采纳。

### 6. 互斥归一

「只看喜欢」和「只看黑名单」互斥（点一个会自动关掉另一个）。存档里两个都为真时
（老版本遗留、或手工改坏），恢复时留「喜欢」、黑名单退回 `hide`：

```js
if (b.onlyLiked && b.blockMode === 'only') b.blockMode = 'hide';
```

### 7. 设置页开关

`config.rememberFilters`（默认 `true`）。加在设置页最上面的「浏览与筛选」分组里。

**关掉时不删已存快照** —— 语义是「不套用」，不是「清空」。再打开时上次的记录还在。

## 三、测试

新增 `_probe/filters-test.js`（**90 断言**，已接进 `test:all`）。

三个函数从 `app.js` **抽出真身**在 vm 里跑，不是复制一份实现：

```
vm.runInContext(SRC + ';({browseFilterSnapshot, applyLastFilters, saveFilters, …})')
```

其中 `_ready(v)` / `_readyVal()` 是插在尾巴上的小钩子，用来翻转/读取 `filtersReady`
这个 `let`（顶层 `let` 不会挂到 sandbox 的 global 上，闭包能碰到）。

钉死的口径：

- 快照**恰好 7 项**、**不含 `search`**、`tags` 是副本（改快照不污染 state）；
- 非法 `sort` / `adultMode` / `blockMode` / `installedSort` 一律退回默认，`showBuiltin`
  非布尔不采纳，`tags` 只留字符串，缺 `browse` 段时已安装排序照样恢复；
- 互斥归一的两个方向（开「喜欢」→ 黑名单退 `hide`；没开 → `only` 合法保留）；
- **启动闸门**：`_ready(false)` 时调 `saveFilters` 等 420ms → 一次都没落盘；
- **防抖**：连调 3 次 → 只落盘 1 次；payload 是 `{ lastFilters: { browse, installedSort, showBuiltin } }`；
- 开关关掉不保存；`config` 还没拿到时不保存也不抛；
- 静态断言：三处挂钩（`loadBrowse` reset / 已安装排序 / 内置脚本开关）、
  `saveFilters` 开头的闸门、`filtersApplied` 守卫、恢复三步的顺序、
  「恢复块在 `renderInstalled()` 之前」、「变了才重拉」、设置页下拉与写回；
- 反向自检：`browseFilterSnapshot` 不得出现 `window.api` / `await` / `fetch`，
  `applyLastFilters` 不得碰 `loadBrowse` / `window.api` / `localStorage`。

> ⚠️ 写「本套件自己不写盘」这条断言时踩了个自指陷阱：正则字面量里写出 `writeFileSync`，
> 而断言又用 `readFileSync(__filename)` 读自己的源码 —— 读到的那段源码里正含着这个词，
> 断言把自己绊倒。改成 `new RegExp('write' + 'FileSync')` 拼出来才干净。

13 个语言包按**同索引**插入（多条新增必须**从后往前插** —— 靠后的先落位，

## 四、遗留

- 快照目前只有一个「槽位」（`config.lastFilters`），没有按分类/游戏分开存。
  以后若要支持多个游戏或「每个分类一套筛选」，结构升级成
  `{ [gameDomain]: { [category]: … } }` 即可，恢复端加一层取值即可，不影响现有断言。
- 已安装页的**搜索/筛选**目前只有排序与内置脚本两项，没有关键词框；
  若以后加了，按本轮口径也应当**不入快照**。
