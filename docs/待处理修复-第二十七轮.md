# 第二十七轮：缺「文件 ID」的任务现在能自己救回来

> 反馈原文：**「依然有无法正常识别的 mod」**（截图：下载管理页）
>
> 截图里那条任务 —— `Planet Diving Suit 2nd Exposed (CNS Compatible)`
> （作者 `PaulR0013 aka nevermore`，13.6 MB）停在「等待授权」，红框里写着：
>
> > 这条任务缺少 Mod ID / 文件 ID，无法自动授权（可点「手动」）。

---

## 一、先分清：这次不是「压缩包结构识别」的问题

上一轮（第二十六轮）修的是**下载完成之后**「无法识别这个压缩包的结构」——
裸包、CNS 数据包、`~Mods` 直投包那几类。

这一条卡在**下载之前**：它连授权都没过，压根还没开始下载。
两者只是在你眼里都表现为「这个 mod 用不了」，成因和代码位置完全不同。

## 二、根因：任务入队时没拿到文件 ID，而授权端点必须按文件 ID 走

任务记录里有三个身份字段：`modId`（哪个 Mod）、`fileId`（哪个文件）、`fileName`。
自动授权走的是 Nexus 站内下载弹层端点：

```
GET /Core/Libs/Common/Widgets/DownloadPopUp?id=<fileId>&game_id=7804&nmm=1
```

**它只认 fileId**。而任务入队时 `fileId` 为空是**常态**，主要有两条来路：

| 入队路径 | 什么时候 fileId 会是空 |
|---|---|
| 浏览页卡片上的「⬇ 下载」 | 你没打开抽屉、或抽屉刚打开**文件列表还没加载完**就点了下载 |
| 浏览页「批量下载」 | 它会给每个 Mod 拉一次文件列表挑主文件，**那次请求失败**就退回「按整个 Mod 入队」 |

老代码在授权前是这么判的：

```js
const modId  = Number(t.meta && t.meta.modId);
const fileId = Number(t.meta && t.meta.fileId) || null;
if (!modId || !fileId) {              // ← 一刀切
  engine.markAuthFailed(id, '这条任务缺少 Mod ID / 文件 ID，无法自动授权（可点「手动」）。');
  return { ok: false, code: 'bad_args', ... };
}
```

问题就在这一刀切：**手里明明有 modId，文件 ID 是随时能查出来的**，
却直接判死、把用户推去点「手动」。这不合算 —— 用户要的正是「不用逐条自己动手」。

## 三、修法：授权前现场查一次主文件，把 fileId 补上再继续

只在 `fileId` 缺失、而 `modId` 在的时候触发：

```
autoAuthorizeTask(id)
  │
  ├─ 没有 modId？          → 明确提示「没有来源 Mod ID」（真的没辙）
  │
  ├─ 有 modId、缺 fileId？
  │     ├─ 调 nexus.getModFiles(modId) 拉文件列表
  │     ├─ 用 pickPrimaryFile() 挑主文件（primary → MAIN → 第一个）
  │     ├─ engine.patchMeta() 把 fileId / fileName / fileVersion / fileSize 写回任务
  │     └─ 继续往下走 ↓
  │
  └─ nexusAutoAuth.fetchNxm({ modId, fileId })   ← 拿 nxm 链接，照常自动下载
```

关键点：

- **挑选口径与界面完全一致**。主进程新增 `nexus.pickPrimaryFile()`，与渲染层
  `app.js` 里的 `pickPrimaryFile()` 判定规则逐条相同（primary 优先 → `categoryRaw === 'MAIN'` → 退回第一个），
  保证「卡片上写的是 A 文件、实际下的是 B 文件」这种事不会发生。有专门的断言跑同一组用例比对两端结果。
- **补齐发生在请求之前**，所以补完能直接用于这一次授权，不用等下一轮。
- **只改 meta、不改状态**。新增的 `engine.patchMeta(id, partial)` 做浅合并，
  任务状态机完全不受影响。
- **补不上才认输**，而且说清是哪种「补不上」。

## 四、提示按原因分层

原来只有一句话，现在分三种，句句告诉用户下一步能干什么：

| 情况 | 提示 |
|---|---|
| 任务确实没有来源 Mod ID | 这条任务没有来源 Mod ID，无法自动授权（可点「手动」）。 |
| Nexus 上确实查不到可下载文件 | 这个 Mod 在 Nexus 上没有可下载的文件，无法自动授权（可点「手动」）。 |
| 文件列表拉取失败（网络/接口） | 取不到这个 Mod 的文件列表（网络或接口问题），稍后再试或点「手动」。 |

这三条**已同步进全部 13 个语言包**（`zh-TW` / `en-US` / `ja-JP` / `ko-KR` / `ru-RU` /
`de-DE` / `fr-FR` / `es-ES` / `pt-BR` / `it-IT` / `pl-PL` / `tr-TR` / `th-TH`），
词条总数 868 → 870，`i18n-check-pack --all` 校验 13/13 通过。

## 六、测试

```
npm run test:all   →  30 个套件 / 1295 断言 / 0 失败（退出码 0）
```

新增的 `_probe/autoauth-fileid-test.js` 共 62 条，覆盖四块：

- **A** `pickPrimaryFile` 的挑选口径（9 个用例，含空数组 / 非数组 / 有空洞 / primary 与 MAIN 并存）；
- **B** 主进程与渲染层**跑同一组用例结果完全一致**（从 `app.js` 抽出函数体实时比对）；
- **C** 接线与顺序：补齐在 `fetchNxm` **之前**、`fileId` 是可变绑定、写回后**立刻广播**、
  `resolvePrimaryFile` 永不抛；
- **D/E/F** 一刀切判定已消失、`patchMeta` 只合并 meta 不碰 status、
  三条新文案同时存在于源码 / 键表 / 13 个语言包。

## 七、你要做什么

1. 在下载页对那条卡住的任务点 **「⚡ 自动授权」**（或顶部「全部自动授权」），
   它会自己把文件 ID 查出来接着下载，**不用再点「手动」**。
2. 如果它仍提示：
   - 「**没有来源 Mod ID**」→ 这条任务是从本地文件导入的，程序确实不知道该去 Nexus 找谁，
     请点「手动」到网页下一个，或直接「移除」这条记录；
   - 「**没有可下载的文件**」→ 作者把文件下架/隐藏了，页面上也没有，只能等作者恢复；
   - 「**取不到文件列表**」→ 网络或 Nexus 接口的问题，过一会儿再点一次即可。
3. 顺手确认一下：点完授权后，卡片上的**文件名 / 体积**是否变成了真实的主文件名
   （补齐成功的话会变准）。
