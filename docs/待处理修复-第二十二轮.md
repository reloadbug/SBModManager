# 「会被覆盖的文件」要说清楚 —— 覆盖明细（第二十二轮）

> 用户反馈（附截图，mod 3023「Tiger Head Necklace - CNS」的安装确认框）：
> 「这种需要覆盖的情况要把被覆盖的文件列出来，**点击后能在资源管理器里面显示出来**；
> **要列出被替换的 mod 文件属于哪个 mod，是否为同一个 mod**。」
>
> 截图里只有一句：「目标位置已有 **2** 个同名文件，继续安装会覆盖它们。」
> —— 不知道是**哪两个**、**谁装的**、**装下去会不会砸掉别的 mod**。
>
> **⚠️ 新代码要重启应用才生效。**

## 一、现在长什么样

下载抽屉 / 确认界面里多了一张清单，每行长这样（一行一颗按钮，**点一下就在资源管理器里选中该文件**）：

```
Minervha_Master_P.ucas        100743776 → 100743776（一样大）
SB/Content/Paks/~Mods/Minervha_Master_P.ucas
【别的 mod】属于「Academy - CNS」v1.0、「Cammy - CNS」v1.0、「Chun Li Bathing suit - CNS」v1.0 等 4 个

some_P.pak                    1000 → 3333（会被替换）
SB/Content/Paks/~Mods/some_P.pak
【不是 mod 装的】游戏原文件（或手动放进去的）

other_P.pak                   2000 → 2000（一样大）
SB/Content/Paks/~Mods/other_P.pak
【同一个 mod】「Tiger Head Necklace - CNS」v2.2 上次装的
```

三处入口共用同一份清单：

| 入口 | 位置 |
|---|---|
| 队列卡片 | 「查看会被覆盖的 N 个文件明细」（只显示前 3 条 + 「还有 N 个没显示」） |
| 下载抽屉 | 「会被覆盖的文件 · N 个」+ 完整清单 |
| 手动安装确认 | 正文里直接插入 |

## 二、排序：**最该看清楚的排前面**

| 顺序 | 情形 | 为什么要看 |
|---|---|---|
| ① | **不是 mod 装的** | 游戏原文件被覆盖，出问题最难查 |
| ② | **别的 mod 装的** | 会破坏别人 |
| ③ | **同一个 mod 自己装的** | 就是升级/重装，最不用担心 |

## 三、🔴 本轮最重要的一条：一条路径可能被**多个** mod 登记

`registry.byTarget()` 用的是 `find` —— **只返回安装顺序上的第一个**。
界面照它显示，就会错报「属于 A」。

本机注册表（101 条）里的真实例子：

```
~Mods/Minervha_Master_P.pak   ← modId 2675 Academy - CNS
                              ← modId 2359 Cammy - CNS
                              ← modId 2705 Chun Li Bathing suit - CNS
                              ← modId 2241 Marin Kitagawa Bikini - CNS
```

这四个 mod 共用同一个**底座 pak**（CNS 服装常见形态）。
只报「Academy - CNS」= 误导。

**修法**：新增 `registry.byTargetAll()`（`filter` 而不是 `find`），
清单渲染 `owners` 数组，多个名字用「、」连接，最多列 3 个 + 「等 N 个」。

同时**收紧「是不是同一个 mod」的判据**：

```js
const isSelf = owners.length > 0 && others.length === 0;   // 登记者全是自己才算升级
```

> ⚠️ 同一路径**既有自己又有别人**时，`isSelf` 必须是 `false` ——
> 覆盖下去照样破坏别人。

## 四、顺带修的两个小东西

- 版本号可能自带 `v`（注册表里就存的是 `v1.0`），原来拼前缀会显示成 **`vv1.0`** →
  加 `/^v/i` 判断
- `path.basename(abs)` 取代 `rel.split('/').pop()` —— 路径落在游戏根之外时
  `rel` 是绝对路径，后者会把整条路径当文件名

## 五、真实体检结果

`node _probe/real-conflict-check.js --all`（本机，library 里 3 个归档）：

```
有冲突的 mod        : 3
冲突文件总条数      : 9（同名同大小 9）
  · 不是 mod 装的   : 0
  · 别的 mod 装的   : 9
  · 同一个 mod 自己 : 0
```

9 条全部撞 `Minervha_Master_P.pak/ucas/utoc`，四个 mod 名字都列出来了 ——
这正是「CNS 服装共用底座」的真实形态，也是**同名同大小（无害覆盖）**的典型。

## 七、你要做什么

**重启应用**（新代码要重启才生效），然后：

1. 下载页点某个「待确认」任务的「去处理」，或点卡片上的
   「查看会被覆盖的 N 个文件明细」；
2. 清单里每行点一下 → 资源管理器里会选中那个文件；
3. 看徽标就知道是「不是 mod 装的」/「别的 mod」/「同一个 mod」。
