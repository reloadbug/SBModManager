# 第三十四轮：已安装 Mod 排序支持正序 / 倒序

用户 2026-10-14 截图（已安装页顶部的排序按钮条：安装时间 / 名称 / Mod ID / 类型）：

> 「@image#1:Clipboard_Screenshot.png 已安装的mod排序要支持正序，倒叙」

诉求很短：**已安装页的排序要能切换正序 / 倒序**。

## 一、口径

### 1. 交互：两种改法，怎么顺手怎么来

- 排序名右侧多一颗**方向按钮**（`↓ 倒序` / `↑ 正序`），点一下翻转；
- **再点一次当前选中的排序名**也能翻转 —— 表格表头的习惯（用户多半会先想到这个）。

两颗入口都走同一个函数 `toggleInstalledSortDir()`。

### 2. 每种排序各有自己的**默认方向**

| 排序 | 默认方向 | 理由 |
|---|---|---|
| 安装时间 | **desc** | 最新装的最上面，符合直觉 |
| 名称 | asc | 字典序从小到大 |
| Mod ID | asc | 数字从小到大 |
| 类型 | asc | 前置组件 → Pak → 逻辑模组 → 脚本 |

**换排序方式时方向回到那个方式的默认值**（`sortDefaultDir(v)`），不用自己再翻一次。
`INSTALLED_SORTS` 每项都显式写了 `defDir`，不靠隐式兜底 —— 测试里钉了这条
（「每种排序都显式声明了 defDir」）。

### 3. 方向也是**筛选条件**

跟着第三十三轮的「记住筛选条件」一起存（`config.lastFilters.installedSortDir`），
下次启动连方向一起还原。三条兜底规则：

- 快照里没有这个字段 → 用**该排序方式的默认方向**；
- 方向是非法值（`'sideways'`）→ 同样退回默认方向；
- **排序方式本身非法**时，方向不单独成立（退回默认 `time` 的 `desc`）——
  否则会得到一个「说不清是什么排序」的方向。

## 二、实现

### 1. `compareInstalled(a, b, mode, dir)` —— 加了第四个参数

```js
const sign = (SORT_DIRS.includes(dir) ? dir : sortDefaultDir(mode)) === 'desc' ? -1 : 1;
```

**不传 `dir` = 用该模式的默认方向**，所以加方向之前的所有调用点与断言行为一字未变
（不用全量改调用点，也保证了老行为不被这轮悄悄改掉）。

### 2. ⚠️ 方向**只作用于主键**，次键不跟着翻转

`time` 模式是「时间 → Mod ID → 名称」三级键，只有**时间**这一级跟 `sign` 走：

```js
if (at !== bt) r = (at < bt ? -1 : 1) * sign;
if (!r) r = byModId(1);    // ← 固定升序
if (!r) r = byName(1);     // ← 固定升序
```

为什么次键不翻：如果整条比较器都乘 `sign`，那「倒序」就成了「正序的**完全逆序**」——
两个方向下的相对次序都得重新解释，用户看到的是「同一批卡片整体洗了一遍」，
而不是「只是把大的排前面」。

### 3. ⚠️ 「没有 modId 的恒排最后」不参与翻转

```js
const byModId = (s) => {
  const av = a.modId || 0, bv = b.modId || 0;
  if (!av && !bv) return 0;
  if (!av) return 1;      // ← 恒排最后，与方向无关
  if (!bv) return -1;
  return s < 0 ? bv - av : av - bv;
};
```

这条约定表示**来源不明**（手动丢进 `~Mods`、未登记的包），是「分类」而不是「大小关系」。
整体取反会把这些包一股脑翻到**最前面**去 —— 用户手动放的几个包突然占了首屏。

同理，**未知 `kind` 在两个方向下都排最后**：

```js
const ra = KIND_RANK[a.kind], rb = KIND_RANK[b.kind];
const ua = ra === undefined, ub = rb === undefined;
if (ua !== ub) r = ua ? 1 : -1;      // ← 方向在这里不参与
else if (ra !== rb) r = ((ra ?? 0) - (rb ?? 0)) * sign;
```

「不认识的类型」不是一个「类型排名值最大」的类型，倒序不该把它顶到最前。

### 4. ⚠️ `groupMtime()` 返回 ISO **字符串**，只能比大小、不能相减

第一版写的是：

```js
r = (at - bt) * sign;     // ❌ 字符串相减 = NaN
```

`'2026-10-14T00:00:00Z' - '2026-10-01T00:00:00Z'` 得到 `NaN`，`r` 永远是 `NaN` ——
`if (!r)` 对 `NaN` 为真（`!NaN === true`），于是主键**静默失效**、一路退化成「按 Mod ID 排」。
症状是「时间的正序 / 倒序点了没反应，而且顺序还不对」——**不会报错**，只会静默出错。

改成：

```js
if (at !== bt) r = (at < bt ? -1 : 1) * sign;   // ✅
```

### 5. UI：排序条包进 `.sortgrp`

```html
<div class="sortgrp">
  <div class="tabs" id="instSort" title="排序方式">
    <button data-isort="time" class="on">安装时间<span class="dir">↓</span></button>
    …
  </div>
  <button class="btn sm" data-isortdir="1" title="切换正序 / 倒序（也可以再点一次排序名）">
    <span class="dir">↓</span><span>倒序</span>
  </button>
</div>
```

两个要点：

- ⚠️ **箭头必须放在独立元素里**（`<span class="dir">`）。i18n 是**按文本节点整串查表**的，
  写成 `${label}${arrow}` 会拼成「安装时间 ↓」，键表里没这条 → **整串都不翻译**。
- ⚠️ **CSS 必须写成子选择器** `.ibar > .btn{margin-left:auto}`：`.ibar` 里现在有两个子元素
  （`.sortgrp` 排序组 + 「显示内置脚本」按钮），后者仍要推到最右。
  写成后代选择器 `.ibar .btn` 会把 `.sortgrp` 里的方向按钮也一起推到最右边去。

```css
.ibar{display:flex;align-items:center;gap:10px;flex-wrap:wrap;margin-bottom:13px}
.ibar > .btn{margin-left:auto}          /* ← 子选择器是关键 */
.sortgrp{display:flex;align-items:center;gap:8px;flex-wrap:wrap}
.tabs button .dir{margin-left:5px;font-size:11px}
.btn .dir{margin-right:3px;font-size:11px}
```

### 6. 点击处理

```js
// 方向翻转（右侧那颗）
const idir = t.closest('[data-isortdir]');
if (idir) { toggleInstalledSortDir(); return; }

// 排序名
const isort = t.closest('[data-isort]');
if (isort) {
  const v = isort.dataset.isort || 'time';
  if (v === state.installedSort) {
    toggleInstalledSortDir();                  // 再点一次当前排序名 = 翻转方向
  } else {
    state.installedSort = v;
    state.installedSortDir = sortDefaultDir(v); // 换排序方式 → 方向回该方式默认值
    renderInstalled();
    saveFilters();
  }
  return;
}
```

`data-isortdir` 的分支必须排在 `data-isort` **之前**（方向按钮不是 `.tabs` 里的按钮，
`closest` 不会误命中；但顺序上靠前更稳妥，跟 `data-iid` 排 `.card` 前是同一个道理）。

## 三、测试

### 1. `installed-merge` 100 → **124 断言**（+24）

`sortDefaultDir` 也是从 `app.js` **抽真身**注入 vm 的（连同 `INSTALLED_SORTS` / `SORT_DIRS`），
不在套件里手抄一份 —— 手抄会漂移。

新增口径：

- `sortDefaultDir`：四个模式各自的默认方向 + 未知 mode 一律 `asc`（不抛异常）；
  `INSTALLED_SORTS` 每项都显式声明 `defDir`；**只有「安装时间」默认倒序**；
- `compareInstalled` 两个方向：`time` / `name` / `modid` / `kind` 在 `asc` 与 `desc` 下都验，
  `time` 的两个方向**互为反号**；
- **不传 `dir` = 默认方向**（`cmp(a,b,'time') === cmp(a,b,'time','desc')`）；
- **次键不翻转**：时间相同时，两个方向下都是 Mod ID 升序；
- **未知 kind 在两个方向下都排最后**；
- 非法方向（`'sideways'`）退回默认；
- 源码接线：`state.installedSortDir: 'desc'`、`sortBar` 是 `.sortgrp`、
  箭头在 `<span class="dir">` 里、`data-isortdir="1"`、「再点当前排序名 = 翻转」、
  `toggleInstalledSortDir` 三件事（翻转 + 重画 + 落盘）、CSS `.sortgrp` 与 **`.ibar > .btn` 是子选择器**。

### 2. `filters` 90 → **103 断言**（+13）

- 正常恢复：`installedSortDir: 'desc'` 被原样采纳（`modid` 默认 `asc`，这个是用户翻过的 `desc`）；
- 缺字段 → 用该排序方式的默认方向（`name` → `asc`、`time` → `desc`）；
- 非法方向 → 退回默认；方向合法但不等于默认值 → **照样采纳**（不因为「等于默认」就丢）；
- **孤立方向**：`installedSort: 'zzz'` + `installedSortDir: 'asc'` → 排序方式退回 `time`，
  方向跟着退回 `desc`（不采纳孤立的 `asc`）；
- payload 里带 `installedSortDir`（默认 `desc`、改完是 `asc`）；
- 三处挂钩的静态断言：换排序方式时方向重置 / 方向按钮 → `toggleInstalledSortDir` /
  `toggleInstalledSortDir` 里也 `saveFilters()`。

## 四、遗留

- 方向是**全局一个**（`state.installedSortDir`），不按排序方式分别记住
  （即「时间记住 desc、名称记住 asc」这种。现在换回时间时会回到 time 自己的默认 `desc`，
  但如果用户上次在时间上手动翻了 `asc`，换到名称再换回来会回到 `desc`）。
  要按方式分别记就得把 `lastFilters.installedSortDir` 升级成对象
  `{ time: 'asc', name: 'desc' }`，恢复端兼容旧字符串即可。当前不觉得有这个必要。
- 浏览页那四种排序（`sort`）**没有**方向开关 —— 用户这次只提了已安装页。
  Nexus 接口本身对「最新 / 最热」这类排序就是**方向既定**的（`updated` 只有倒序），
  客户端翻不了；若要支持，得把列表整体 reverse，与「喜欢的稳定置顶」会不会打架要单独想清楚。
