# 统一 Mod 页面设计（浏览 / 已下载 / 已安装 合并）

> 目标：一套界面同时管理「在线 Mod」「已下载的安装包」「已安装的文件」，消除三页之间的重复功能。
> 本文只描述现状与方案，落地按最后的「分期」走。

---

## 一、现状盘点

### 1.1 三个页面各自有什么

| 能力 | 浏览页 `p-browse` | 下载页 `p-download` | 已安装页 `p-installed` |
|---|---|---|---|
| 关键词搜索 | ✅ `#searchInput`（走 Nexus 服务端） | ❌ | ✅ `#instSearch`（就地过滤：名字/ID/作者/文件名/`nx<tag>`） |
| 排序 | ✅ 下载最多 / 最多点赞 / 最新发布 / 最近更新 | ❌（按状态分组） | ✅ 名称 / Mod ID / 类型 / 大小 / 时间 + 正倒序 |
| 分类 / 标签筛选 | ✅ 分类单选 + 标签多选并集（带计数） | ❌ | ✅ 类型下拉 `#instKind` |
| 状态筛选 | 只显示未安装 / 已下载 / 只看喜欢 / 黑名单三态 / 成人三态 | ✅ 进行中 / 已暂停 / 待处理 / 待安装 / 已安装 / 失败 | ✅ 全部 / 已启用 / 已关闭 / 部分启用 / 未登记 / 已关联 / **有 bug / 不含 bug** |
| 卡片封面 + 摘要 | ✅ | 部分（安装包卡片有名/版本/大小） | ✅（未登记时显示「本地文件 无封面图」） |
| 👍 / 👎 | ✅ `voteHtml` | ❌ | ❌（抽屉里也没有） |
| 多选 | ✅ 全选 + 批量下载 | ❌ | ✅ 全选 + 批量启用 / 关闭 / 卸载 |
| 主操作 | 下载 / 安装到游戏 / 已安装 / 查看进度 | 暂停 / 继续 / 取消 / 授权 / 确认安装 / 一键安装 / 打开文件夹 / 彻底删除 | 开关 / 卸载 / 标 bug / 取消关联 |
| 详情抽屉 | ✅ 图集 + 文件列表（可单文件下载）+ 投票 + 打开网页 | ❌（只有动作按钮） | ✅ 图集 + 说明 + 来源 + 信息 + 逐文件开关 |

### 1.2 明确的重复项

1. **卡片**：浏览页 `browseCard()`、已下载清单的库卡片 `libCardHtml()`、已安装 `installedCard()` —— 三份封面/标题/作者/版本/角标排版几乎一样。
2. **搜索**：`#searchInput`（在线）与 `#instSearch`（本地）是两套输入框、两套语义。
3. **筛选条**：`#browseHead` 与 `.ibar` 各有一套「状态 + 分类 + 排序 + 多选」，只是取值集合不同。
4. **多选 + 批量**：`state.sel`（浏览）与 `state.gsel`（已安装）两套状态、两组按钮。
5. **抽屉**：`openNexusDrawer()` 与 `openInstalledDrawer()` 都在画图集、来源、文件列表、动作区。
6. **状态判定**：`localState.js`（在线→已下载/已安装）与 `groupInstalled()`（磁盘→分组）两套口径，靠 `modId` 勉强对齐。

### 1.3 数据现状（关键）

| 数据 | 文件 / 位置 | 主键 | 备注 |
|---|---|---|---|
| 已安装登记 | `<data>/mods.json` | 记录 `id` = `nexus:<modId>:<fileId>` 或磁盘条目 id | 有 `manifest`（绝对路径）、`enabled` |
| 批量解析关联 | `<data>/mod-links.json` | `disk:<...>` / `nexus:<modId>:<fileId>` | 未登记条目靠它认 Nexus |
| 已下载安装包 | `library` 目录扫描（`localLibrary.scan`） | 文件名解析出的 `modId` | 无 fileId |
| 下载任务 | `<data>/downloads.json` | `taskId` | 有状态机 |
| 👍 喜欢 | `<data>/favorites.json` | **只有 modId** | 存了 name/author/thumbnail，可离线渲染 |
| 👎 黑名单 | `<data>/blacklist.json` | **只有 modId** | 同上 |
| ⚠ bug 标记 | `<data>/bugs.json` | **只有 modId** | 同上 |
| Mod 基本信息缓存 | `<data>/cache/mod-info/<modId>.json` | modId | 目录命中就不联网 |
| 图片缓存 | `cache/images/<modId>/` | modId | 图集/封面 |

> ✅ **好消息**：👍/👎/⚠ 三份用户数据本来就是「以 Nexus modId 为键、与文件无关」的，
> 天生满足「删掉文件但保留用户数据」。合并界面不需要动它们的数据结构。

## 二、统一数据模型

一条 **Mod 记录**（逻辑对象，不落盘）由五个来源拼出来：

```
modId（Nexus ID，唯一键）
 ├─ 元信息   : catalog / cache/mod-info（名字、作者、版本、摘要、封面、赞数、成人）
 ├─ 本地文件 : 已安装 manifest（可能多组） / library 里的安装包 / ~Mods 里未登记的 pak 组
 ├─ 传输状态 : downloads.json 里的任务（queued…installing / failed）
 └─ 用户数据 : liked / blocked / bug / note（互相正交）
```

### 2.1 派生状态（不存储，实时算）

```
            ┌──────────── 卸载 ────────────┐
            ▼                              │
  在线 ──下载──▶ 已下载 ──安装──▶ 已安装·已启用 ⇄ 已禁用
   ▲              │                    │
   └── 删安装包 ───┘                    └── 有部分文件启用 = 部分启用
```

- **主状态**（互斥，按优先级）：`installing` > `downloading` > `installed` > `downloaded` > `online`
- **子状态**：`installed` 再分 `enabled` / `disabled` / `partial`
- **正交标记**（可叠加，各显示小角标）：`liked` / `blocked` / `bug` / `unregistered`(没有 modId) / `linked`(批量解析关联的)

### 2.2 无 modId 的本地条目怎么办

`~Mods` 里手放的 pak 组可能没有 `[nx<id>]`、也没登记、没关联 —— 它们的键用
`disk:<相对路径>`，**不参与** 👍/👎/bug（没有 Nexus ID 可关联），但仍然出现在「已安装」筛选里。
一旦「批量解析」把它们关联上（`mod-links.json`），记录自动升级为 `modId` 键，用户标记立刻可用。

## 三、界面方案

### 3.1 结构：一个页面 + 状态筛选

**把「浏览 Mod」改造成「Mod 库」**，页面内不再分「在线列表 / 已下载列表」，只分状态：

```
┌─ 顶栏（吸顶） ──────────────────────────────────────────────┐
│ [🔍 搜索 Mod 名称 / ID / 作者]      [⬇ 下载队列 3]  [刷新]   │
│ 状态: 全部 1779 · 在线 1340 · 已下载 222 · 已安装 118 · 已禁用 12 · 部分启用 3 │
│ 标记: 👍喜欢 42 · 👎不感兴趣 91 · ⚠有 bug 1        [正序/倒序 ▾] │
│ 分类: 全部 · 服装 779 · 角色预设 292 …  标签: CNS · 替换 · …（可多选）│
│ [☑ 多选] [全选] [批量下载] [批量安装] [批量启用] [批量禁用] [批量卸载] [标 bug] │
└──────────────────────────────────────────────────────────────┘
  ↓ 卡片网格（同一张卡片，状态不同动作不同）
```

**要点**
- 关键词一个输入框：搜到本地条目就本地匹配，同时可用它去 Nexus 搜（回车才走服务端，避免每敲一个字打网络请求）。
- 已安装页的 `#instSearch`、`.ibar`、`sortBar` 与下载页的 `dl-*` 工具条全部退役，功能并入这一条。
- 「已安装 Mod」「下载」两个左侧导航项保留但瘦身：
  - **已安装 Mod** → 变成同一页面的「状态=已安装」预设入口（点了就等于把状态筛选切到已安装）。
  - **下载** → 只保留「传输 / 安装队列」（进行中的进度、失败重试、授权），不再列已完成的 Mod 卡片。

### 3.2 卡片（唯一一种）

```
┌─────────────────┐
│  封面（本地缓存优先）│  ← 右上：状态徽标（已安装/已下载/下载中/在线）
│  ✓ 勾选框（多选时） │  ← 左上：⚠有 bug 红标 / 👍 小图标
├─────────────────┤
│ 标题              │
│ 摘要（1 行）       │
│ #4102 v1.2 作者 · 12.4 MB · 3 个文件          │
│ [主按钮] [次按钮] [⋯]                        │
└─────────────────┘
```

主按钮随主状态变：

| 主状态 | 主按钮 | 次按钮 |
|---|---|---|
| 在线 | 下载 | 👍 / 👎 / ⋯ |
| 下载中 / 排队 | 查看进度 | 暂停 / 取消 |
| 已下载 | **安装到游戏** | 打开文件夹 / 🗑 删安装包 |
| 已安装·已启用 | 已安装 ✓（点开详情） | 禁用 / 卸载 |
| 已安装·已禁用 | 已禁用（点开详情） | 启用 / 卸载 |
| 部分启用 | 部分启用 | 全部启用 / 全部禁用 |

`⋯` 菜单里放低频动作：标 bug / 打开 Nexus 网页 / 刷新图集 / 重新下载 / 定位文件。

### 3.3 详情抽屉（唯一一个）

一个抽屉，按记录状态显示不同区块，不再区分「在线抽屉 / 已安装抽屉」：

1. 头图 + 标题 + 作者 + 版本 + `#modId` + 状态徽标
2. 👍 / 👎 / ⚠ 标 bug / 打开网页（**同一行，一直是这四个**）
3. 说明（本地档案优先，缺了才联网补）
4. **文件**：分两段
   - 「在线文件」（需要授权/下载的，逐个给「下载」或「安装到游戏」）
   - 「本地文件」（已装进游戏的文件，逐个给开关 + 路径 + 大小）
5. 安装包 / 来源 / 位置 / 时间等信息表
6. 图集
7. 底部动作：安装到游戏 / 卸载 / 删安装包（互斥出现）

### 3.4 多选与批量（唯一一套）

`state.selection`（合并现在的 `state.sel` 与 `state.gsel`）：存 `{ mode:'mod'|'lib', keys:Set }`。

批量按钮按**选中集合的构成**动态显示可用项：

| 选中的构成 | 可选批量动作 |
|---|---|
| 全是「在线」 | 批量下载 |
| 全是「已下载」 | 批量安装 / 批量删安装包 |
| 全是「已安装」 | 批量启用 / 批量禁用 / 批量卸载 |
| 混合 | 只显示对全部适用的（如「标 bug」），并提示「这批里有 N 个状态不同，只显示通用操作」 |

## 四、数据一致性

### 4.1 单一事实来源

| 事实 | 唯一来源 | 谁负责写 |
|---|---|---|
| 装没装 / 开关 | 注册表 `mods.json` + 磁盘文件存在性（`reconcile.js` 核对） | 安装器 / `setEnabled` |
| 下没下 | `library` 目录扫描 + 下载任务 | 下载引擎 / 安装器 |
| 名字作者版本封面 | `cache/mod-info/<modId>.json` → 目录 → 联网 | `modInfo` |
| 👍/👎/⚠ | `favorites/blacklist/bugs.json`，键=modId | 渲染层投票 / 标 bug |

**判定顺序固定**：主进程算好 `localState`（含 library、registry、tasks）→ 渲染层只做展示，不再各自猜。

### 4.2 删除语义（用户 2026-11-10 明确要求）

三个「删」必须分清，且**都不删用户数据**：

| 动作 | 删什么 | 保留什么 |
|---|---|---|
| 禁用 | 只把文件改名（`.disabled` / `.dekcns.disabled.json`） | 全部 |
| 卸载 | 还原备份、删游戏目录里的文件、`mods.json` 记录降级为「已下载」（安装包还在） | 安装包 + 👍/👎/⚠ |
| 删安装包 | 只删 `library` 里的压缩包 | 注册表记录（若仍装着）+ 👍/👎/⚠ |

- 抽屉里提供单独的、**要二次确认**的「清除我的标记（喜欢/不感兴趣/bug）」——只有用户主动点才清。
- 「彻底删除」（下载页的 `dl-purge`）＝ 卸载 + 删安装包 + 删任务，同样**不动** marks。

### 4.3 一致性检查（已有 `reconcile.js`）

启动时按磁盘核对：移除失效记录 / 裁剪丢失的文件 / 纠正开关（现在已认 `.dekcns.disabled.json`）。
新增一条：**安装包丢了但标记还在** → 记录降级为「在线」，标记保留（这正是用户要的行为）。

## 五、迁移与分期

| 期 | 内容 | 风险 |
|---|---|---|
| **P1** | 浏览页状态筛选扩展：`已下载` 从「独立清单」变成状态过滤；搜索框统一；卡片组件抽成一份 `modCard(rec, {mode})` | 低。现有 `onlyDownloaded` 已是雏形 |
| **P2** | 已安装页并入：`.ibar` / `installedCard` / `gsel` 退役，改走统一卡片与统一选择集；「已安装 Mod」导航项变成状态预设 | 中。批量启停卸要重接（`gselBatchToggle` 等已有实现可复用） |
| **P3** | 抽屉合并：一个 `openModDrawer(modId)`，在线/本地区块按状态组装 | 中。图集、文件列表、动作区都要合并 |
| **P4** | 删除语义与标记保留：三个「删」分清 + 「清除我的标记」入口 + `reconcile` 新增「包丢了标记保留」 | 低 |
| **P5** | 下载页瘦身为队列视图（进行中/失败/授权），已完成的不再列卡片 | 低 |

每期都要：`node --check` → 相关 `_probe` 断言 → 全量探针 → `--shot` 真机截图 → 版本号 + CHANGELOG → 打包 + `build/portable.js`。
