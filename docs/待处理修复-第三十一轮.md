## 一、先别急着骂作者

红字把锅直接甩给了作者 —— 「作者只开了手动下载」。这是我们自己的文案写的，但**这个结论很可能是冤枉的**。

`no_nxm`（弹层里给不出 `nxm://` 链接）其实有**两种**成因，老代码只认第一种：

| # | 成因 | 站方表现 | 用户该做什么 |
|---|------|---------|-------------|
| ① | 作者逐文件关掉了「管理器下载」 | 弹层里只有手动下载按钮 | 点「手动授权」，或去网页手点 |
| ② | **文件刚上传，Nexus 还在往文件服务器同步** | 弹层里写着 *The file is currently being uploaded to our file servers and it will be ready to be downloaded soon.* | **等几分钟**，再点「自动授权」 |

第 ② 种情况下，用户点「手动授权」同样拿不到链接 —— 因为链接**根本还不存在**。老文案把用户引向了死路，还顺带冤枉了作者。

### 现场取证

没法直接复现弹层（运行中的 Electron 独占 Cookie 库，`cp` / `copyFileSync` / `File.Open` 全 EBUSY，见「踩坑」段），改走 **Nexus GraphQL 的文件时间线**：

查 `modFiles(modId: 3982)`，失败文件 `fileId 17324` 与同作者的成功文件对比：

| fileId | 上传时间（UTC） | 任务创建时间 | 上线到重试的间隔 | 结果 |
|--------|----------------|-------------|-----------------|------|
| **17324** | 2026-10-14 **13:41:28** | 13:43:59.678Z | **仅 151 秒** | ❌ 失败 |
| 3985 | 3.7 小时前 | — | 数小时 | ✅ 成功 |
| 3986 | 18.8 小时前 | — | 数小时 | ✅ 成功 |
| 1711 | 10562 小时前 | — | 很久 | ✅ 成功 |

**决定性差异只有一个：`date`（上传时刻）。**

全字段 diff 掉失败/成功文件：`manager`、`category`、`primary`、`scannedV2` **全都一样** —— 不是文件属性问题，是**时间**问题。一个上传 151 秒的文件，被我们当场判了「作者不给你下载」。

WebSearch 也印证了这一点：刚上传的文件在 Nexus 同步到文件服务器并完成扫描之前，不会提供「管理器下载」入口。

## 二、修法：两种成因分流，并按时间等一等

### 1. 认页面措辞（`parsePopup`）

弹层 HTML 里如果没有 `nxm://`，**先看页面有没有写「还没就绪」**：

```js
const NOT_READY_RE = /currently\s+being\s+uploaded\s+to\s+our\s+file\s+servers
  |will\s+be\s+ready\s+to\s+be\s+downloaded\s+soon
  |not\s+yet\s+available\s+for\s+download
  |file\s+(?:is\s+)?not\s+ready/i;
```

命中 → `{ ok:false, code:'file_not_ready' }`；否则才是 `no_nxm`。

判定顺序固定为：**challenge → not_logged_in → file_not_ready → no_nxm**。
（有 Cloudflare 挑战或有登录问题时，那些更该先说，不能被「还没就绪」盖住。）

### 2. 认上传时间（主判据，`ipc.js`）

页面措辞会变、会本地化，所以**真正的主判据是文件的上传时刻**。新增 `fileAgeMs()`：

```js
async function fileAgeMs(modId, fileId) {
  const files = await nexus.getModFiles(Number(modId));
  const f = (files || []).find(x => Number(x.fileId) === Number(fileId));
  const d = f && Number(f.date);
  if (!d) return null;          // ⚠️ 不能用 0 兜底，否则「查不到」会被当成「刚上传」
  return Date.now() - d * 1000;
}
```

判定抽成**纯函数** `settleDecision()` 放进 `nexusAutoAuth.js`（这样测试能真跑它，而不是正则匹配源码）：

```js
const FILE_SETTLE_MS = 3 * 60 * 1000;        // 3 分钟宽限期
const FILE_SETTLE_WAIT_MAX_MS = 60 * 1000;   // 最多等 60 秒

function settleDecision(o) {
  const code = o && o.code;
  const age = (o && Number.isFinite(o.ageMs)) ? o.ageMs : null;
  const fresh = age != null && age >= 0 && age < FILE_SETTLE_MS;
  const notReady = code === 'file_not_ready' || (code === 'no_nxm' && fresh);
  const wait = (notReady && fresh) ? Math.min(FILE_SETTLE_MS - age, FILE_SETTLE_WAIT_MAX_MS) : 0;
  return { notReady, wait };
}
```

三条设计要点：

- **`ageMs == null` 一律不按未就绪处理** —— 查不到时间就老实说「没链接」，绝不能把「作者真关了」洗成「稍后再试」，让用户白等。
- **宽限期定 3 分钟**：现场 151 秒正是典型；而上线超过 3 分钟还拿不到链接，基本就是真的没有。
- **等待有上限（60 秒）**：按剩余时间等，最多 60 秒，然后**再问一次**。不让用户干等一个 `await` 卡住界面。

### 3. 失败文案分开（`humanize`）

```js
case 'file_not_ready':
  return '这个文件刚上传，Nexus 还在把它同步到文件服务器，暂时给不出管理器下载链接。过几分钟再点「自动授权」即可。';
```

老文案（作者只开了手动下载）**保留不动** —— 真·没链接时它是对的。

### 4. 日志留证据

- 判定未就绪时打 `download:fileNotReady`，带 `ageMs` / `waitMs` / `rawCode`；
- 失败时打 `download:autoauthFailed`，新增 **`snippet`** 字段（弹层 HTML 剥掉标签、压空白、截断 400 字）—— 下次再遇到，日志里就有站方原话可查，不用再猜。

`fetchNxm()` 的「不必重试」清单也补上 `file_not_ready`（重试也是白重试）。

## 三、踩坑记录

### Electron Cookie 库被硬锁

想直接复现弹层响应（拿 `Cookie` 手动 curl 那个 `DownloadPopUp` 端点），结果：

- `cp Cookies /tmp/` → `Device or resource busy`
- `fs.copyFileSync` → `EBUSY`
- PowerShell `File.Open` → 「正由另一进程使用」

运行中的 app 独占 `%APPDATA%/剑星 Mod 管理器/Partitions/nexus/Network/Cookies`。
**结论：离线复现弹层不可行**，只能靠 GraphQL 时间线 + 社区资料交叉取证。

### 别用 `0` 兜底 `date`

`Number(f.date)` 缺失时如果 `|| 0`，`Date.now() - 0` = 天文数字年龄 → `fresh = false` → 恰好「看起来对」，
但语义是错的（把「查不到」当成「很老」）。显式 `if (!d) return null;`，让调用方区分「未知」与「已知很老」。

## 四、测试

- `autoauth-test` 68 → **105 通过 / 0 失败**（+37 条），新增三段：
  - **A3b 失败分类**：站方原话 / `ready to be downloaded soon` / `not yet available` / 大小写变体 → `file_not_ready`；
    **真·没链接仍是 `no_nxm`**（不洗白作者）；challenge / not_logged_in **优先于** file_not_ready；
    `snippet` 剥标签、压空白、有上限；成功时不带 snippet。
  - **A5 `settleDecision` 真身行为**：用现场数据（151 秒）断言 `notReady:true` 且 `wait = 180s − 151s`；
    3.7 小时 → 不就绪；**`ageMs: null` → 不就绪**（防洗白，关键）；边界 `= FILE_SETTLE_MS`；
    `wait` 被上限截断；`file_not_ready` 无时间也 `notReady:true`（但不等）；负数 / NaN / 缺参不炸。
  - **C2 ipc 接线**：调 `settleDecision`、`fileAgeMs` **只查一次**、`!d` 返回 null、只有两种码才查、
    错误码统一、`sleep(d.wait)` 后重试、两条日志（含 snippet）、`fetchNxm` 不重试 file_not_ready、
    `markAuthFailed` **不改状态**（按钮还在，可重试）、新文案确在键表与 13 包内、旧文案未被删。

- i18n：键表 985 → **986**，13 个语言包同步；`i18n-check-pack.js --all` → **13/13 全部 986/986、0 不合格**。
