# 已安装页：显示 Mod ID + 一键定位原压缩包（第二十五轮）

> 用户诉求：
> 「已安装的 mod 要显示 mod id，提供 library 中的原压缩包的链接，
> 点击后直接在资源管理器中定位压缩包。」
>
> **⚠️ 新代码要重启应用才生效。**

---

## 一、Mod ID 显示出来了

两处都显示：

| 位置 | 显示 |
|---|---|
| **卡片** | 封面下方那行多了一个蓝色等宽徽标：`#1312 v2.3 xNumber7x 15.6 MB · 3 个文件` |
| **详情抽屉 → 信息** | 新增一行 `Mod ID`：`#1312 · 文件 5836` |

- `#1312` 是 **Nexus Mod ID**（Nexus 网址 `/mods/` 后面那个数字）；
- `文件 5836` 是**文件 ID**（同一个 Mod 可能有多个文件，这是你装的那一个）。

实测 114 张卡片里 113 张带徽标 —— 唯一的例外是 **UE4SS**（内置前置组件，没有 Nexus 来源）。

> 磁盘上扫描到的、不是本程序安装的模组（「未登记」）没有 Mod ID，
> 卡片上就**不会**出现一个空的 `#`。

## 二、原压缩包：一键在资源管理器里定位

详情抽屉里新增「**原压缩包**」区块，抽屉底栏也多了一个 **📦 定位原压缩包** 按钮。

```
原压缩包
┌────────────────────────────────────────────────────────────┐
│ 1312_A2 Midriff with Clean Oiled Body Sliders…_v1.0.zip  [在资源管理器中定位] │
└────────────────────────────────────────────────────────────┘
来自内置库 data/library/ · 4.4 MB
```

点「在资源管理器中定位」→ 资源管理器打开 `data\library\` 并**选中那个压缩包**。

### 四种情况都如实说，不给点了没反应的链接

| 情况 | 界面 |
|---|---|
| 压缩包还在 `data\library\` 里 | 文件名 + 「在资源管理器中定位」+「来自内置库 `data/library/`」 |
| 还在，但不在内置库（当时是手动导入的） | 同样给定位按钮，注明「不在内置库 `data/library/` 里」 |
| **文件已经不在磁盘上了** | 按钮**置灰**、文件名加删除线，并把原路径写出来（方便自己去找 / 重下） |
| 没有安装包记录（磁盘扫描到的模组） | 直接说明「这是磁盘上扫描到的模组，不是本程序装的」 |

> 🔧 为什么要这么细：注册表里存的是**安装当时**的路径。实测你这台机器 101 条记录里
> 97 条还在 `data\library\`、1 条在 `D:\Downloads`、**4 条文件已经没了**。
> 如果直接拿记录里的路径去打开，那 4 条会「点了什么都不发生」——
> 用户只会以为是程序坏了。所以现在**每次打开都重新确认一次文件还在不在**。

## 三、顺手修掉的小 bug

卡片上的版本号原来会显示成 **`vv2.3`**（Nexus 的版本号本身就带 `v`，代码又拼了一个 `v`）。
现在统一走一个 `verText()`：`2.3 → v2.3`、`v2.3 → v2.3`。

## 六、你要做什么

**重启应用**（新代码要重启才生效），然后：

1. 进「已安装 Mod」页 —— 每张卡片封面上方/下方能看到蓝色的 `#数字` 徽标；
2. 点任意一张卡片打开右侧详情 —— 「信息」里有 `Mod ID` 行；
3. 往下滚一点，找到「**原压缩包**」—— 点「在资源管理器中定位」，
   资源管理器会打开 `data\library\` 并选中那个压缩包；
4. 抽屉底栏也有一个 **📦 定位原压缩包**，效果一样。

> 如果你的某条记录显示「文件已不在这个位置」，说明那个压缩包被删/移走了 ——
> 程序会把它当时的完整路径写出来，方便你自己去找或者重下。
