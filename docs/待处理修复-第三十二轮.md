# 第三十二轮：把 👍 / 👎 下移到下载按钮旁，操作类按钮集中

用户 2026-10-14 截图追加：

> 「喜欢和不喜欢按钮下移，与下载按钮放在一起，操作类的按钮尽量集中」

截图里那张卡（YoRHa Unofficial Ceremonial Attire…）：

```
┌─────────────────────────────┐
│ 成人内容            ✓ 已安装 │
│                             │
│        [封面图]        👍👎 │ ← 红框圈的是这对，压在图上
│ 服装                        │
│ YoRHa Unofficial …          │
│ Completely modular …        │
│ v1.1.0  Njaescha ⬇62.6万 ♥8105  [已安装] │
└─────────────────────────────┘
```

诉求很清楚：把封面右上那对图标**挪下去**，和卡片底部的动作按钮凑在一起。

## 一、问题

上一轮（同日）把「🚫 不喜欢」文字按钮换成了 👍/👎 一对纯图标，位置沿用老布局 ——
`position:absolute; bottom:8px; right:8px` 贴在**封面右下角**。它有两个别扭：

1. **压住封面图**：封面本来就不大，右上角还有「✓ 已安装」「成人内容」角标，右下再叠一对按钮，
   图被啃掉一块；
2. **和动作按钮隔着一条街**：卡片底部的「⬇ 下载 / 已安装」在 `.meta` 行，
   投票按钮却浮在图上 —— 都是「点一下做点什么」的操作，却分成两处。

## 二、改法

### 1. 结构：投票按钮搬进 `.meta` 行，包一个 `.acts` 容器

```js
// 封面里只留角标（已安装 / 分类 / 成人内容），不再有 voteHtml
<div class="cover">…</div>
<div class="cbody">
  <h3>…</h3><div class="zh">…</div>
  <div class="meta">
    v1.1.0  作者  ⬇ 下载量  ♥ 点赞数
    <div class="acts">${voteHtml(n)}${action}</div>   ← 投票 + 下载按钮同处一室
  </div>
</div>
```

`.acts` 用 `margin-left:auto` 把这一组推到行末 —— 左边是元信息、右边是操作，一眼分明；
行内挤不下时 `.meta` 本来就 `flex-wrap:wrap`，会自动整组换行且仍靠右。

### 2. 样式：从「压在图上」改成「和按钮同一层」

`.vote` 去掉 `position:absolute`，`.vbtn` 的背景从 `rgba(20,22,26,.88)`（半透明深色 + 投影，
是为盖在封面上准备的）换成 `var(--panel2)`（普通面板色）；点亮态的底色也从不透明深色
换成 14% 透明的彩色，跟 `.btn.st-ok` 之类的按钮观感统一。

```css
.acts{display:flex;align-items:center;gap:6px;margin-left:auto}
.vote{display:flex;gap:5px}                    /* 不再是 absolute */
.vbtn{…;background:var(--panel2);…}            /* 去掉 box-shadow */
.vbtn.up.on  {color:#7ED8A0;background:rgba(63,185,80,.14)}
.vbtn.down.on{color:#F0908C;background:rgba(217,83,79,.14)}
```

### 3. 文案：空态提示里的「右下角」要跟着改

「只看喜欢 / 只看黑名单」的空态提示原本写「**在卡片右下角点 👍** 就会收在这里」——
位置变了，这句话就成了错指路。改成「**点卡片上的 👍** 就会收在这里。」

两条文案都是 **i18n 键**（原文即 key），而且改头两个字会让它在**码点排序**里的位置变化。
所以这次的 i18n 脚本（`_probe/_rekey-31.js`）不是「插一条」而是「改键 + 重排」：

1. 键表里就地替换两条 → 重算排序 permutation；
2. **用同一个 permutation** 重排 13 个语言包的数据行 → 键表与包仍严格同序；
3. 每个语言包都带了同序自检（第 N 行的旧键必须正好是那两条，否则抛错），避免错位误伤。

13 个语言包的译文也一并去掉了「右下角 / bottom-right / 오른쪽 아래 / มุมล่างขวา」这类位置说法。

## 三、影响面

`browseCard()` 是浏览区**唯一的卡片渲染函数**，被 4 处调用：

| 位置 | 用途 |
|---|---|
| `app.js:1602` | 单个卡片替换（投票后局部重画） |
| `app.js:1795` | 列表批量渲染 |
| `app.js:1843` | 更新单张卡片 |
| 「只看喜欢 / 只看黑名单」 | 复用同一条渲染路径（本地数据源） |

所以改这一个函数，浏览页、本地记录视图、多选/批量那几处的卡片**同时**生效，没有漏网。

## 四、测试

`favorites` 97 → **101 通过**（+4），断言跟着改：

- 新增 `CSS 有 .acts 容器（margin-left:auto 推到行末）`；
- 原「`.vote` 绝对定位贴在封面右下角」改为**反向断言**：
  `.vote` 必须是 `display:flex` **且不得**再出现 `position:absolute`（防止有人改回去）；
- 新增 `👍/👎 与「下载 / 已安装」按钮同处 .acts 容器`（直接匹配
  `${voteHtml(n)}${action}` 这一段字面量）；
- 新增「投票按钮在 `.cbody` 内」——用 `indexOf` 比较 `voteHtml(n)` 与 `<div class="cbody">`
  的先后，确保它**不再画在封面里**；
- 空态提示文案两条都改了口径断言。

i18n：键表仍 986 条（改 2 条不增数），`i18n-check-pack.js --all` → **13/13 全部 986/986、0 不合格**。
