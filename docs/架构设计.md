# 剑星 Mod 管理器 · 架构设计（v1 待评审）

> 目标：一个 Windows 桌面程序，负责《剑星》(Stellar Blade) 的 mod 加载器部署、mod 安装/卸载/管理、Nexus Mods 浏览与一键安装、说明中文化。

## 1. 加载器分层（这是剑星 modding 的既定结构）

```
① UE4SS                —— 脚本注入/运行时钩子（"mod 加载器"本体）
   SB\Binaries\Win64\dwmapi.dll      (DLL 代理，游戏启动即加载)
   SB\Binaries\Win64\ue4ss\          (运行时 + Lua Mods 目录)
        └─ Mods\<脚本mod>\Scripts\main.lua

② Custom Nanosuit System (CNS) —— 服装/外观系统框架（mod #1496，绝大多数服装 mod 的前置）
   SB\Binaries\ + SB\Content\        (整目录合并到 SB\)
   游戏内按 N 键呼出菜单

③ 普通 mod
   SB\Content\Paks\~Mods\*.pak       (外观/贴图/模型替换，多数)
   SB\Binaries\Win64\ue4ss\Mods\     (逻辑类 Lua mod)
```

> 关键结论：**"mod 加载器" ≠ 单个软件，而是 ①UE4SS + ②CNS 两个前置**。管理器必须能检测/安装/修复这两者。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 外壳 | **Electron**（内置 Chromium + Node） | 需要真实浏览器内核浏览 Nexus（Cloudflare + 登录态 + JS 渲染）、需要注入脚本、需要 `nxm://` 协议注册、需要文件系统操作 |
| 主进程 | Node.js（Electron 内置） | 下载/解压/安装/文件监听 |
| 渲染层 | 原生 HTML/CSS/JS（无框架） | 体积小、可控、易维护 |
| 内嵌浏览 | Electron `WebContentsView` | 与主 UI 同窗口，可注入 preload |
| 存储 | JSON 文件 + 本地缓存目录 | 无需数据库，便于备份/迁移 |
| 打包 | electron-builder → 免安装绿色版 | 双击即用 |

**备选方案（不推荐）**：Python + PySide6（WebEngine 安装体积大、注入能力弱）；Tauri（需 Rust 工具链，本机未安装）；纯浏览器扩展（无独立"程序"形态，卸载/文件管理受限）。

## 3. 三条安装通路（覆盖你提的全部场景）

### 通路 A — 粘贴链接导入
```
粘贴 https://www.nexusmods.com/stellarblade/mods/1496?tab=files
  → 解析 game=stellarblade, modId=1496
  → Nexus API 拉元数据（名称/作者/说明/图片/文件列表）
  → 图集走隐藏窗口读 mod 页（API 无按 mod 的图集字段），缓存 TTL 7 天
  → 弹窗选择要装的文件（Main / Optional / Old）
  → 进入下载
```

### 通路 B — 手动下载 + 自动导入（★ 你截图里选的方式）
```
网页点 [Manual download] → 文件落到系统「下载」目录
  → 管理器目录监听发现新压缩包
  → 匹配待安装队列 / 自动识别 mod 名
  → 解压 → 策略引擎判定落点 → 安装 → 记账
```
兼容：拖拽 zip 进窗口、`选择本地文件` 按钮。

### 通路 C — 浏览器里的「安装到本地」按钮（★ 已按 Cloudflare 现实修正）
```
你在自己的浏览器（Edge/Chrome）里正常逛 Nexus —— 登录态、验证 cookie 都是现成的
  → 浏览器扩展 / 用户脚本在 mod 页面注入「⬇ 安装到本地」按钮
  → 点击后有两种走法：
      ① Mod 管理器下载（推荐）→ 脚本代点页面上的 "Mod manager download" → 拿到 nxm:// → 管理器接管下载
      ② 手动下载 → 脚本代点 "Manual download" → 文件落盘后管理器自动导入（同通路 B）
```

**为什么改成"你自己的浏览器"而不是"内置浏览器"**：见 §3.5。这是本次架构最重要的一处修正。

## 3.5 关于 Cloudflare 人机验证（必须正视）

### 现象与根因（已实测排查）
| 检查项 | 结果 |
|---|---|
| 系统 WinINET 代理 | **已启用**：`ProxyEnable=1`，`ProxyServer=127.0.0.1:26797`（本机科学上网客户端），Chrome/Edge 默认走它 |
| WinHTTP 代理 | 直接访问（无代理） |
| `curl https://www.nexusmods.com`（直连） | 403 |
| `curl https://www.nexusmods.com`（走代理） | 403 |
| `curl https://api.nexusmods.com/v1/games/stellarblade/mods/1496.json` | **401 + 干净 JSON**（`{"message":"Please provide an authentication method"}`）—— **无验证码拦截** |

**结论**：网站域名被 Cloudflare 的 Bot 防护挡着，而 API 子域是干净的。403/验证码主要由**出口 IP 信誉**（代理节点是被滥用的机房 IP）触发，不是针对你的账号。

### 处理原则
1. **不做验证码绕过**。自动化破解 Turnstile 违反 Cloudflare 与 Nexus 的服务条款，且会让本机 IP / 管理器被永久拉黑，属于自毁行为。
2. **能不走浏览器就不走浏览器**。把绝大多数功能迁移到不受挑战影响的通道：

| 功能 | 通道 | 是否受验证码影响 |
|---|---|---|
| 搜索 / 元数据 / 说明 / 图片 | `api.nexusmods.com` + 个人 API Key | ❌ 不受影响（实测可达） |
| 下载 | `nxm://` 协议（Nexus 官方为第三方管理器设计的通路） | ❌ 不受影响 |
| 浏览网页（可选功能） | 你自己的浏览器 | 你已登录、已过验证，cookie 现成 |

3. **内置浏览器降级为可选**。若保留，遇到挑战时**弹提示让用户手动点一次**（Turnstile 就是个勾选框），通过后把 `cf_clearance` cookie 持久化到会话分区复用，之后长期不再出现。绝不静默重试、绝不模拟点击。
4. **建议你在代理客户端里加一条直连规则**：`DOMAIN-SUFFIX,nexusmods.com,DIRECT`（Nexus 主站国内一般可直连）。换一个未被滥用的节点也能立刻消除挑战。
5. **管理器的 HTTP 客户端必须显式配置代理策略**：默认直连 API，不走系统代理，避免继承被污染的出口 IP。

### 关于"Nexus 免费账号能否自动下载"——必须说清楚的技术边界
- Nexus **官方 API 的直链下载接口仅对 Premium 会员开放**。免费账号通过 API 拿不到文件直链。
- 免费账号的合法自动下载通路是 **`nxm://` 协议**：网页上点 "Mod manager download" 时，Nexus 会给登录用户签发一个**带 key 和过期时间的临时链接**（Vortex / MO2 就是这么工作的）。我们注册 `nxm://` 协议处理器，即可合法接管。
- **前提：必须在浏览器里登录 Nexus 账号**（你截图里显示 "You have to be logged in to download files"）。
- 若要走元数据/搜索（通路 A），需要一个**免费的 Nexus 个人 API Key**（账号设置 → API 页生成）。
- 不做爬虫：元数据走官方 API，浏览走真实浏览器内核，规避 Cloudflare 与 ToS 风险。

## 5. 关键流程

### 5.1 安装流程
```
拿到压缩包
 → 解压到临时沙箱 data/tmp/<uuid>/
 → 结构嗅探（strategies.js）：
     顶层有 ue4ss/ + dwmapi.dll      → 策略 UE4SS_ROOT
     顶层有 Binaries/ + Content/     → 策略 GAME_SB_ROOT（CNS 类）
     顶层有 ~Mods/ 或 *.pak          → 策略 PAKS_MODS
     顶层有 Scripts/main.lua 或 *.lua → 策略 UE4SS_SCRIPT
     其它                            → 策略 UNKNOWN（弹窗让用户手选落点，并记住规则）
 → 冲突检测：目标文件已存在且不属于同一 mod → 提示覆盖/跳过/改名
 → 执行复制（覆盖前先备份到 data/backup/<modId>/）
 → 写 manifest + 注册表
 → 刷新 UI
```

### 5.2 卸载流程
```
按 manifest 删除该 mod 新增的全部文件
 → 还原被覆盖的备份文件
 → 清理注册表 + 可选保留/删除归档
```

### 5.3 启用/禁用
- `~Mods` 类：文件重命名为 `xxx.pak.disabled`（UE4 不会加载非 `.pak` 后缀）—— 无损可逆。
- UE4SS 脚本类：改写 `ue4ss\Mods\mods.txt` 中的 `0/1` 开关。

## 9. 翻译方案

| 后端 | 是否需 Key | 说明 |
|---|---|---|
| MyMemory API | 否 | **默认**。实测本机可直连。有速率限制，适合按需翻译 |
| Bing 翻译 | 否 | 备用 |
| 大模型 API（OpenAI 兼容 / DeepSeek 等） | 是 | 质量最好，适合长说明，可选填 |

策略：**按需翻译 + 结果永久缓存**（`cache/meta/<modId>.zh.json`）。原文与译文并存，UI 上「中文 / English」一键切换，绝不覆盖原文。

> 实测：本机 `translate.googleapis.com` 不可达；MyMemory 与 Bing 可达。

### 9.1 界面多语言（i18n，2026-10-14 追加）

⚠️ 与上面第 9 节不是一回事：第 9 节翻译的是 **Mod 说明文本**（英→中，机器翻译），
本节翻译的是**程序自己的界面**（原文是简体中文）。

| 项 | 值 |
|---|---|
| 语言数 | **14**（简体中文即原文，无语言包；另 13 种带完整语言包） |
| 代码 | `zh-CN`(原文) / `zh-TW` / `en-US` / `ja-JP` / `ko-KR` / `ru-RU` / `de-DE` / `fr-FR` / `es-ES` / `pt-BR` / `it-IT` / `pl-PL` / `tr-TR` / `th-TH` |
| 词条数 | 每包 **868 条**，与 `_probe/i18n-keys.json`（唯一真源）逐条对应 |
| 运行时 | `src/renderer/i18n.js`（先建 `window.I18N`，语言包往里 `register()`） |
| 语言包 | `src/renderer/locales/*.js` |

**核心做法：中文原文即 key + 渲染后 DOM 后处理。**

- 业务代码**一行都不用改**：`app.js` 照旧渲染中文，`i18n.js` 在渲染完成后遍历 DOM 查表替换；
- `originals` Map 记住每个文本节点的原文 → 切换语言幂等，可以来回横跳，不会「翻了再翻」；
- `MutationObserver` 盯新增节点，异步渲染（列表/抽屉）也能翻到。

**查表三段兜底**（DOM 里的文本常带数字与符号，整串永远对不上）：

1. 整串命中；
2. 从两头剥掉「非词字符」后再整串命中（`个 Mod` 这类）；
3. 片段替换（按 key 长度降序，长的先跑，避免短键吃掉长键的前缀）。

**数字模板（`%s` 形状键）**：模板字面量里 `${n}` 与周围文字在 DOM 里**属于同一个文本节点**
（只有 HTML 标签才切分节点），所以 `共 ${a} 项 · ${b} 个已启用` 是一个节点而字典只有两头片段时，
替换完数字会卡在中间、语序读不通。解法是把数字位写成 `%s`，匹配时通配数字串
（`(\d[\d,.\s]*\d|\d)`，`3,027` 一次吃完），命中后把实际数字**原样回填**。

> **验收口径的例外**：片段替换的「结果不能残留汉字」这条，对 **zh-TW / ja-JP** 天然不成立
> （译文本身就是汉字/假名）。这两种语言只要求「确实替换过」，否则片段通路 100% 失效、
> 用户看到的还是简体原文。

**加载方式**：界面 CSP 是 `script-src 'self'`，`file://` 下 `fetch` 读不了本地 JSON，
所以语言包一律用 `<script>` 引入，且顺序必须是 `i18n.js` → 13 个语言包 → `app.js`。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| Nexus 未登录 → 无法下载 | 内置浏览器内嵌登录页；UI 显式提示登录状态 |
| 免费账号无 API 直链 | 走 `nxm://` 协议（合法且为 Nexus 官方支持的第三方管理器通路） |
| Cloudflare 拦截 | 不使用爬虫；元数据走官方 API；浏览用真实 Chromium 内核 |
| 压缩包结构千奇百怪 | 策略引擎 + 未知结构手选 + 规则记忆 |
| 卸载残留 | 安装即记账（manifest），卸载按清单精确回滚 |
| 游戏更新导致 mod 失效 | 记录游戏 exe 版本与 mod 版本，变更时高亮提示 |
| 覆盖原版文件导致游戏损坏 | 覆盖前强制备份，提供「还原原版」按钮 |

## 12. 待你确认的事项

1. **技术栈用 Electron 吗？**（会下载约 100MB 运行时；换来的是真浏览器内核 + 注入 + 协议接管）
2. **翻译后端**：默认 MyMemory（免费无需 Key）可以吗？你是否有大模型 API Key 想接进来？
3. **Nexus API Key**：需要你去 `nexusmods.com/users/myaccount?tab=api` 生成一个个人 Key（免费）给我，用于拉取 mod 名称/说明/图片。**这是绕开 Cloudflare 挑战的关键**——有了它，搜索/元数据/图片全部走 API，完全不需要碰网页。
4. **Nexus 账号**：需要登录（免费注册即可），否则任何下载通路都走不通。
5. **界面风格**：深色游戏风（见原型）是否满意？
6. **浏览器扩展**：接受安装一个本地扩展（Edge 加载解压扩展即可）来实现网页内「安装到本地」按钮吗？如果不想装扩展，可退化为「手动复制链接粘贴进管理器」。

## 13. 需要你在本机做的两件事（消除验证码）

1. **代理客户端加直连规则**：`DOMAIN-SUFFIX,nexusmods.com,DIRECT`，或换一个节点。
2. 遇到 Turnstile 时**手动点一下复选框**（它只是个勾选框，不是拼图），通过后 cookie 会长期复用。

> 我实测：`api.nexusmods.com` 在你这台机器上返回干净 JSON，**没有任何验证码**。所以只要把功能迁移到 API + `nxm://` 两条通道上，验证码问题基本就从工作流里消失了。
