## 二、三处规则修正

### 1. 纯 CNS 数据包 → 落 `~Mods`

CNS 的数据文件本来就住在 `~Mods` **根级**，和 pak 并排 —— 游戏目录里的实况：

```
SB\Content\Paks\~Mods\bcasecoolingsuit.dekcns.json
SB\Content\Paks\~Mods\CNS-Ultimate-1690.dekcns.json
```

这类包的作用是**改写已装 CNS 服装的外观定义**（换脸、换配色），落点必须和 pak 一致，
否则游戏读不到。新增规则：文件全是 `.dekcns` / `.dekani` 且**全在根级** → 落 `~Mods`。

### 2. 作者的工程源文件 → 给结论，不给「手选目录」

`.blend` / `.psd` / `.fbx` / `.spp` / `.xcf` / `.kra` 这些是**做 mod 用的原料**。
以前报「结构无法识别，需要手动指定安装位置」，用户真的去找目录 —— 而**装到哪儿都不会生效**。
现在直接给结论，并且不给手选入口：

> 这是作者的工程源文件（.blend），不是能装进游戏的 Mod，装到哪个目录都不会生效

### 3. 「覆盖自己」不算冲突

同一个 Nexus mod 换了 fileId 重新下，两个包的文件名往往**一模一样**
（`56_156_P.pak/.ucas/.utoc` + `Modified Neurolink Suit.dekcns.json`），
于是 4 个文件全部命中 `existsSync` → 被判成「有 4 个文件会被覆盖，等你确认」。

现在按 **`source.modId` 认亲**（不看 fileId）：命中「自己已装的文件」一律不算冲突 → 自动升级安装。

## 三、变体包：从「选一套」改成「多选」

### 发现 1：一个包里可能有好几个**互不相关**的 mod

实测 **mod 3970「Nv_pu_CNS」**，三个子目录是：

```
Nv_pu_CNS\Nv_pu_CNS\          主 mod（nvpu_P.pak + .dekcns.json）
Nv_pu_CNS\Ahuang_Skin3.0\     Ahuang 皮肤（Ahuang_Skin2161_P.pak）
Nv_pu_CNS\中文楷体Mod\          中文字体（Kaiti_CH3155_P.pak）
```

老界面按「3 选 1」处理 → 用户**永远只能装到其中一个**。现在可以全选一起装。

### 发现 2：判断「会不会互相覆盖」要看**资产 ID**，不是文件名

```
mod 692:  ID77117-BP_Nude_Planet Diving Suit (7th)_A_P.pak
          ID77117-BP_Nude_Planet Diving Suit (7th)_B_P.pak     ← 文件名不同，ID 相同
mod 437:  77117-Planet_Diving_Suit (7th)_A_P.pak
          ID77117-Planet_Diving_Suit (7th)_D_P.pak             ← ID 前缀可写可不写！
```

所以多选时按资产 ID 分组，**ID 相同 = 同一件东西的不同版本**，只能挑一套。
真选了两套会明确报「有 N 处会互相覆盖」并让你重选，**不会静默装歪**。

真实归档按 ID 分组的实测结果：

| mod | 候选数 | 按资产 ID 分组 | 建议 |
|---|---|---|---|
| **437** BP Planet Diving Suit (7th) | 9 | `ID77117` ×6（A~F）、`ID77127` ×1、`ID77137` ×2 | 每组挑一套 = **选 3 套** |
| **692** Eve BP Nude | 7 | `ID77117`×2、`ID77127`×2、`ID99001`×2、`ID390001`×1 | 每组挑一套 = **选 4 套** |
| **3970** Nv_pu_CNS | 3 | 文件名里没有资产编号 → 三套互不相关 | **3 套全装** |
| **347** Nikke Cooling Suit Plus | 6 | 没有资产编号 | 界面只提示「同一件东西只能装一套」，由你判断 |
