# SBModManager — 剑星 Mod 管理器

《剑星》(Stellar Blade) 的 Windows 桌面模组管理器。

- 项目主页：<https://github.com/reloadbug/SBModManager>
- 更新日志：[`CHANGELOG.md`](CHANGELOG.md)
- 问题反馈：<https://github.com/reloadbug/SBModManager/issues>

> 仓库名 / 包名 / 安装包文件名是 **SBModManager**；程序内显示的标题仍是「剑星 Mod 管理器」
> （保留显示名是为了不改 `userData` 目录名 —— 改了老用户的设置与 Nexus 登录态就会「消失」）。

## 启动

### 用打包好的 exe（推荐）

到 `dist/` 里拿：

| 文件 | 说明 |
|---|---|
| `SBModManager-0.2.0-setup.exe` | 安装版（约 106 MB）。可选安装目录，装完有桌面/开始菜单快捷方式 |
| `SBModManager-0.2.0-portable.exe` | 便携版（约 106 MB）。双击即用，不写注册表 |

两者都**不需要管理员权限**，也都**不会**在卸载时删你的数据。

### 从源码跑

双击 **`启动.bat`** 即可。会留一个控制台窗口，关掉它等于关掉程序。

如果窗口闪一下就消失，双击 **`启动-兼容模式.bat`**。

命令行方式：

```bash
npm install     # 首次
npm start
```

### 关于"闪退"与兼容模式

部分 Windows 环境（虚拟机 / 远程桌面 / 驱动异常 / 受限会话）**无法建立 Chromium 的进程沙箱**，
表现是 GPU 进程反复崩溃，随后 Electron 直接 `FATAL: GPU process isn't usable` 退出。
实测单独加 `--disable-gpu` 无效，必须加 `--no-sandbox`。

程序已内置自动处理：**启动 20 秒内检测到 GPU 崩溃 → 自动以兼容模式重启一次 → 并把选择记住**。
所以正常情况下你什么都不用做，顶多第一次启动会闪一下再弹出来。

| 启动参数 | 作用 |
|---|---|
| 无 | 正常模式（保留沙箱与硬件加速） |
| `--compat` | 兼容模式：`--no-sandbox` + 软件渲染 |
| `--gpu` | 强制正常模式（忽略已记住的兼容模式） |
| `--dev` | 打开开发者工具 |

> 兼容模式会关闭 Chromium 的渲染进程沙箱。本程序只加载本地页面，
> 远程内容仅限 `<img>` 里的封面图，不加载任何远程网页，因此这个取舍是可接受的。

```bash
npm test              # 主进程模块自检（游戏探测 / 扫描 / Nexus / 翻译）

npm run test:autoauth # 免点击自动授权（弹层端点解析 / 失败分类 / 串行流水线 / 挑战页冷却续跑）
npm run test:conflicts # 覆盖明细（归属三态 / 多主路径 / 大小对比 / 排序 / limit / 渲染层接线）
npm run test:blacklist # 浏览页吸顶 + 黑名单（本地 CRUD / 前端筛选口径 / 接线）
npm run test:top-account # 顶栏账号头像（判定脚本抽真身 / 缓存有值才覆盖 / 三态渲染）
npm run test:archive  # 已安装页 Mod ID + 原压缩包定位（archiveInfo 跑真身 / 四种状态 / 版本号不拼 vv）
npm run test:e2e-ue4ss # UE4SS 真实安装 → 卸载 的端到端（含「重装不重复备份自己」）
npm run probe:nxm     # 下载引擎自检（真实 HTTP 写盘 / 进度 / 取消 / 链接解析）
npm run dev           # 带开发者工具
npm run shot          # 截图到 _shots/preview.png
npm run dist          # 打包 exe（NSIS 安装版 + 便携版）→ dist/
npm run dist:dir      # 只出未压缩目录 dist/win-unpacked（快，用于本地验证）
npm run icon          # 重新生成应用图标（build/icon.png + build/icon.ico）
```

> 自动化截图/探针要用 **`node _probe/launch.js`** 拉起 Electron，不要直接跑 `electron.exe`：
> 本机沙箱下从 Git Bash 直接执行 `electron.exe` 会**静默失败**（进程不起、退出码 0、日志空），
> 症状和「单实例锁被占用」一模一样。`launch.js` 用 Node 的 `spawnSync` 接管管道就正常了。
>
> ```bash
> node _probe/launch.js --compat --shot=_shots/x.png --shot-page=p-download --shot-delay=6500
> node _probe/launch.js tests/selftest.js            # 第一个参数是 .js 时当作 app 入口
> ```
>
> 如果 `launch.js` 报 `SPAWN_ERROR ... EBUSY`（某些沙箱环境会拦住 Node 的 `spawnSync`），
> 改由 shell 直接执行即可 —— 同一个 exe 由 shell 起是通的：
>
> ```bash
> env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/electron.exe tests/selftest.js
> ```

## 数据目录

**数据目录的位置取决于是从源码跑还是用打包好的 exe：**

| 运行方式 | 数据目录 |
|---|---|
| 源码（`npm start`） | `<项目>/data/` |
| 打包版（exe） | `%APPDATA%\剑星 Mod 管理器\data` |

打包版之所以换地方，是因为 `__dirname` 在 `app.asar` 里是只读归档，写不进去。
放到 `%APPDATA%` 还有个好处：**卸载程序不会删你的数据**（`deleteAppDataOnUninstall: false`）。

> ⚠️ 两边是**两套独立的注册表**。如果你一直在用源码版、现在想切到打包版，
> 跑一次搬迁脚本即可（会一并重写注册表里的绝对备份路径）：
>
> ```bash
> node _probe/migrate-data.js            # 预演，只报告
> node _probe/migrate-data.js --apply    # 真正执行
> ```
>
> Nexus 登录状态是**共享的**（存在 Electron 的 userData 里），不用重新登录。

目录内容：

| 路径 | 内容 |
|---|---|
| `config.json` | 配置（游戏目录、API Key、翻译目标语言、下载目录监听开关） |
| `mods.json` | 已安装 Mod 注册表（含回滚清单与覆盖备份指针） |
| `downloads.json` | 下载队列（**不含**授权 key/expires） |
| `watch-seen.json` | 下载目录监听已处理过的文件（避免重复提示） |
| `library/` | 下载归档（平铺单目录），文件名 = `id_模组名_版本.扩展名`，如 `533_Cake Unveiled ..._6.0.zip`；保留原始压缩包便于重装 |
| `cache/images/<modId>/` | Mod 封面与预览图本地缓存（一个 mod 最多 **5 张不同图片**，同一张图的不同尺寸只留一份） |
| `cache/gallery/<modId>.json` | Nexus mod 页图集缓存（TTL 7 天，抓不到自动回落官方封面） |
| `backup/overwritten/` | 覆盖安装前的原文件备份 |
| `blacklist.json` | 浏览页黑名单（点了「不喜欢」的 mod）。纯本地，删掉即清空 |
| `backup/uninstalled/` | 卸载时移出的文件 |
| `logs/` | 主进程日志，按天轮转保留 7 天 |
| `tmp/` | 解压临时目录。每次安装自动清理；删不掉的会改名成 `*.trash-<时间戳>`，由后台清扫收走 |

## 打包

```bash
npm run dist        # → dist/SBModManager-<版本>-setup.exe   + -portable.exe
npm run dist:dir    # → dist/win-unpacked/（不生成安装包，快）
```

几个注意点：

- **打包入口是 `build/dist.js`，不是直接调 electron-builder。** 它负责设好两个镜像：
  `ELECTRON_MIRROR` 与 `ELECTRON_BUILDER_BINARIES_MIRROR`（都指向 npmmirror）。
  本机 `github.com` 直连不通，不换镜像的话 nsis / winCodeSign 这些打包辅助二进制根本拉不下来。
- **重新打包前先 `rm -rf dist`。** electron-builder 会删掉上次的 `dist/win-unpacked`，
  在受限沙箱里可能触发批量删除保护而直接失败。
- 图标由 `build/make-icon.py`（纯 Pillow 矢量绘制）生成，改完设计跑 `npm run icon` 即可。
- 打包产物约 106 MB/个，主要是 Electron 运行时（`app.asar` 本身只有 400 KB 左右）。

## 关于 Nexus 的三个技术事实

1. **浏览不需要 API Key。** 元数据走 `api.nexusmods.com` 的公开 GraphQL 接口，
   实测未登录即可读取 mod 名称、说明、图片、文件列表。在设置里填个人 API Key 可获得更高配额。
2. **下载必须登录 Nexus 账号。** 管理器采用 `nxm://` 协议接管（Nexus 官方为第三方管理器
   提供的通路），不抓取网页、不绕过 Cloudflare 人机验证。
3. **免费账号没有纯 API 下载通路。** 实测直接调 `download_link.json` 会返回
   `403 this is for premium users only`；授权链接只能由 Nexus 在**用户点一下**的瞬间签发。
   本程序的做法是：带上你的登录会话，直接调用**网页按钮背后的那个站内端点**
   （`/Core/Libs/Common/Widgets/DownloadPopUp?...&nmm=1`）来等价地「点」那一下 ——
   实测 38/38 命中，所以不必再逐个去网页点。**不伪造 key**：key 始终由 Nexus 为你签发。
   链接有时效，过期后重试一次即可。

## 下载与安装怎么用

### 推荐方式：浏览页点「⬇ 下载」（全自动）
1. 登录 Nexus（设置页 → Nexus 账号 → 登录 Nexus）。
2. 「浏览 Mod」页挑一个 → 卡片上点 **⬇ 下载**。
3. 程序会**自动授权并开始下载**，接下来全部自动：取直链 → 下载 → 识别结构 → 安装 → 登记。
4. 进度在「**下载**」页看，已安装页顶部也会显示正在处理的项。

> **登录一次就够了。** 早期版本要你在 Nexus 网页上对**每一个** Mod 点一次
> 「Mod Manager Download」—— 因为免费账号没有会话级下载授权，Nexus 只在
> 「用户点一下」的瞬间签发带 `key`/`expires` 的一次性链接。
> 现在程序**直接调用 Nexus 网页按钮背后的那个站内端点**（带上你的登录会话），
> 等价于替你点了那一下，所以不再需要逐个去网页点。
>
> 边界（刻意保留）：**不绕 Cloudflare 人机验证、不伪造 key、不抓网页**。
> 万一撞上验证页，程序会自动冷却后重试；连续多次都被拦才停下并提示你。

### 浏览页：顶部栏吸顶 + 「不喜欢」黑名单

**顶部栏吸顶**：排序、显示范围（成人内容 / 只显示未安装 / 黑名单）、分类标签筛选、
统计行都固定在顶部，往下翻多少都不会消失 —— 想换排序或筛选不用滚回最上面。

**「不喜欢」**：每张卡片底部都有一个 **🚫 不喜欢** 按钮。点一下：

1. 这张卡片**立刻**从列表里消失（不用等）；
2. 记进本地黑名单 `data/blacklist.json`，以后不再显示；
3. 顶部统计行会注明「已隐藏黑名单（共 N 个）」。

顶部那一组 **隐藏黑名单（默认）/ 显示全部 / 只看黑名单** 用来控制：

| 选项 | 效果 |
|---|---|
| **隐藏黑名单**（默认） | 拉黑过的 mod 不出现 |
| 显示全部 | 黑名单也一起显示（临时看看） |
| **只看黑名单** | 只列黑名单里的 mod —— **秒开**（直接读本地记录，不联网） |

在「只看黑名单」里，卡片上的按钮会变成 **♻ 移出黑名单**，点了就恢复显示。

> 黑名单**只存在本地**（按 Nexus modId 认），不上传、不同步到 Nexus 账号。
> 想彻底清空就删掉 `data/blacklist.json`。

### 队列里攒了一批「等待授权」怎么办？

下载页顶部有个 **⚡ 全部自动授权（N）** 按钮，点一次把 N 条全部放行，
然后它们会自己排队下载安装。也可以在设置页把授权方式固定成「自动」，
之后新任务入队即自动授权，完全不用管。

想回到「逐个去网页点」的老流程，把设置页的授权方式改成「手动」即可。

### 一个 Mod 有多个文件？
详情抽屉的**文件列表里，每个文件后面都有自己的「⬇ 下载」** —— 点哪个就只下载哪个文件
（body / 贴图 / 可选组件各取所需），入队时就把文件钉死，之后 Nexus 页面只高亮那一行。
抽屉底部那颗按钮则对准**主文件**。下载管理页的每条任务会显示文件名，同一 Mod 的多个任务分得清。

### 从 Nexus 网页直接下载
先到设置页点 **注册为默认处理器**（让系统把 `nxm://` 交给本程序）。
之后在 Nexus 的 Mod **Files** 页点 **Mod Manager Download**，系统会自动调起本程序；
链接一到就**直接进下载队列**开始下载，不需要再确认一次。

### 下载管理页
| 状态 | 含义 | 能做什么 |
|---|---|---|
| 等待授权 | 已入队，还没拿到授权 | **⚡ 自动授权**（推荐）/ 手动授权 / 取消 |
| 排队中 · 获取链接 · 下载中 | 自动进行中 | 取消（会清掉半截文件） |
| 已下载 | 下载完了，但没游戏目录等原因没装 | 安装 / 打开文件夹 |
| 待确认 | 结构不认识 / **有文件会被覆盖** / 包里有多套内容 | 确认安装 / 打开文件夹 / 移除 |
| 安装中 | 正在解压复制 | 取消 |
| 已安装 | 装好了 | 重新安装 / 打开文件夹 / 删除记录 |
| 失败 · 已中断 | 出错（附人话原因） | **去处理**（包还在）/ 重试（包没了）/ 打开文件夹 / 移除 |

- 队列**持久化**：关掉程序再打开，进行中的任务会标成「已中断」，点重试即可。
- 同一个 Mod 重复加入会**复用同一条记录**，不会在列表里堆一串同名任务。
- 下载归档保留在 `data/library/`（按 `id_模组名_版本` 规范命名），删掉原下载文件也能重装。
- **「已安装」页顶部有一条实时条**：正在下载/安装的直接看进度；
  「待处理」的会写明**为什么要你处理**并给一个「去处理」按钮 —— 这类任务是**在等你**，
  不是在跑，所以不会转圈。

### 一个包里有多套内容（多选一变体包）

有些服装 Mod 会把**同一件衣服的几套配色/版本**各放一个子目录，例如：

```
BP_Nude_Skin Suit (2 variants)\BP_Nude_Skin Suit_A\ID99001-..._P.pak
BP_Nude_Skin Suit (2 variants)\BP_Nude_Skin Suit_B\ID99001-..._P.pak
```

也有包会把**几个互不相关的 mod 打在一起**（实测 `Nv_pu_CNS` = 主 mod + 皮肤 + 中文字体）。

所以对话框是**多选**：列出所有候选（带**预览图**、文件数、体积、**资产 ID**），点一下勾选，
再点「安装选中的（N）」。**打开时已经替你预选好了**：

- **互斥组**（含同一件东西的几套，标着 `第 N 组 · 只能选一套`）→ 每组预选第一套；
  点同组另一套会自动换过去（组内单选）。
- **不在任何组里的**（互不相关的几套）→ 全部预选，直接装就是对的。
- 判据是**资产 ID 相同**（`ID77117` 出现在两套里）；没有资产编号的包退化成
  「pak 文件名相同」。真选了两套，程序会明确报「有 N 处会互相覆盖」并让你重选，
  **不会静默装歪**。
- **每套显示预览图**：很多包在根级放「一套一张图、文件名=目录名」
  （`Cooling suit_A/` ↔ `Cooling Suit_A.jpg`）—— 不看图根本不知道哪套是什么颜色。
  图是**按需从压缩包里解出来的**（只解那几张，不全解），缓存在 `data/cache/variants/`。
  包里没图就不显示图位。
- 选中的内容会**拍平**放进 `~Mods`（游戏只从 `~Mods` 根级加载 pak）。
- 没选中的不会安装；想换，回到「下载」页重新点「确认安装」即可。

> 作者在说明里常写「drag and drop **the folder** into ~mods」——
> 那只是让手动安装的人少点几下。pak 的内部挂载点由 pak 自身决定，
> 跟文件放在哪个目录无关，所以**拍平到根级**是等效且更稳的做法
> （社区指南 Fextralife 也是这么写的：*Drop the `.pak` … into `~mods`*）。

### 有些包「装不了」不是 bug

- **只有 `.dekcns` / `.dekani`**（CNS 外观数据，没有 pak）→ 自动装进 `~Mods`，
  和 pak 并排（CNS 就是这么读的）。
- **整包都是作者的工程源文件**（`.blend` / `.psd` / `.fbx` / `.spp` …）→
  程序会直接告诉你「这不是能装进游戏的 Mod，装到哪个目录都不会生效」，
  卡片上给的是「移除」而不是「确认安装」。
- **覆盖自己上一个版本**（同一个 mod 换了 fileId 重新下）→ 算**升级**，不算冲突，
  会照常自动安装并备份。
- **自带同一个底座 pak**（Minervha 系的 CNS 服装 mod 每套都带
  `Minervha_Master_P.pak/.ucas/.utoc`，和游戏里那份**逐字节一致**）→
  判定为「同名同大小 = 同一个文件」，不算冲突，直接覆盖（覆盖前照旧备份）。
  否则每装一个这类 mod 都会弹一次「有 3 个文件会被覆盖」。
- **包里分了 A/B/C 几套 → 那是要你挑一套，不是「结构无法识别」**。
  程序识别是成功的，文案会写成「包里有 N 套内容，需要你选要装哪些」；
  点「确认安装」就弹出带预览图的选择框，而且**每组已经预选好了**。
- 很多包会在里面放一份说明（`Installation instructions.txt` / `readme.txt`）。
  遇到拿不准的包，**先解压看有没有这份说明** —— 作者写的才是最准的。

想换一套，回「下载」页重新点一次「确认安装」。

> 顺带堵掉一个坑：带子目录的纯 pak 包**不会**再被直接丢进 `~Mods` 根目录 ——
> 游戏只加载 `~Mods` **根级**的 pak，放错层级等于白装。


### 用本地压缩包安装
点顶部 **＋ 导入 Mod** → **选择本地压缩包**，支持 `.zip` / `.7z` / `.rar`。
导入后同样进入下载队列（状态直接是「已下载」），随即自动分析 + 安装。
包会复制一份到 `data/library/` 并统一改名为 `id_模组名_版本`，所以之后清空下载文件夹也不影响重装。

### 手动下载也会被自动发现
如果你在 Nexus 点了 **Manual download** 存到本地，程序会自动认出来并导入，不用手动拖进来。

- **设置 → 下载目录监听**：默认监听系统「下载」文件夹，可以自己加目录。
- 只有**文件不再变大**之后才会导入，不会把下到一半的包吃进去。
- 认得出 Nexus 的文件名（`名字-<modId>-<版本>-<时间戳>.zip`）时，会**自动补全来源**
  （Mod 页面链接、封面、说明），和从队列下载的效果一样。
- 认不出来的包也能导入，只是没有来源信息。
- 刚启动时会**静默扫一遍**已有文件，不会把你下载夹里躺着的旧包全弹出来 ——
  想主动导入点「立即扫描」；想彻底忽略已有的点「忽略现有」。

### 一键安装前置组件（CNS）
**前置组件**页 → CNS 卡片 → **一键安装 CNS**。

会打开一个内嵌的 Nexus 窗口，直接落在 CNS 的 Files 页，并把该点的按钮**高亮出来**。
在窗口里点那个绿色的 **Mod Manager Download**（不要点 Manual download），
本程序就会自动接管下载 → 识别 → 安装到 `SB\`。

如果窗口顶部提示 **请先登录 Nexus**，点窗口右上角的 **Log in** 登录即可（登录一次长期有效）。

如果顶部出现红色「**被 Cloudflare 人机验证拦住了**」，点右侧「重新加载」多试几次；
仍然过不去就改用 **从本地压缩包安装** —— 那条路完全不依赖 Nexus 网页。

CNS 依赖 UE4SS，没装 UE4SS 时这个按钮会是灰的。

### 一键安装 UE4SS
UE4SS 不在 Nexus 上（它是 GitHub 上的开源项目），所以走**另一条下载通道**。

**前置组件**页 → UE4SS 卡片 → 会先显示查到的**最新版本号**，点 **一键安装 UE4SS** 即可。
程序会从 GitHub Release 下载正式发布包，剥掉外层包装目录，把 `dwmapi.dll` 放到
`SB\Binaries\Win64\` 根、`ue4ss\` 整目录搬过去 —— 这个位置放错加载器就不工作，
所以落点规则是**专门为它写死**的，不走通用推断。

> 本机实测 `github.com` 直连不通，但 `api.github.com` 与发布资产 CDN 是通的，
> 所以默认走官方「资产 API」通路，不需要额外配置。
> 如果你有自己的加速镜像，可以在设置页填 GitHub 镜像地址，它会作为第三条备选通路。

### 装服装 Mod 时会提示需要 CNS
服装类 Mod（`.dekcns` / 落在 `CustomNanosuitSystem\` 下的文件）**必须**有 CNS 才会生效。
程序在安装前就能认出来，缺 CNS 时不会白装：

- 下载队列里，这类任务会停在「**待确认**」，并直接说明「这是服装 Mod，需要先安装 CNS」；
- 确认安装的弹窗里也有一条红色提示 + 「先去装 CNS」按钮，点了直接跳到前置组件页。

装完 CNS 回到「下载」页点「确认安装」即可。

### 安装时会发生什么
程序会先读压缩包结构，自动判断属于哪一层：

| 识别结果 | 落点 |
|---|---|
| Pak 模组（`.pak` / `.ucas` / `.utoc`，**全在包根层**） | `SB\Content\Paks\~Mods\` |
| 脚本模组（Lua） | `SB\Binaries\Win64\ue4ss\Mods\<包名>\` |
| 框架包（同时含 `Content\` 与 `Binaries\`，或自带 `SB\` 目录） | 合并到 `SB\` |
| **UE4SS 本体**（根级 `dwmapi.dll` + `ue4ss\`） | 原样落到 `SB\Binaries\Win64\` |
| **纯 CNS 数据包**（只有 `.dekcns` / `.dekani`，没有 pak） | `~Mods\`（和 pak 并排，CNS 就是这么读的） |
| **一个包里多套内容**（同一件衣服的多个版本，或几个互不相关的 mod） | 列出来让你**多选**，带预览图、按互斥组默认预选（同资产 ID 的只能挑一套） |
| **整包都是作者的工程源文件**（`.blend` / `.psd` / `.fbx` …） | 不安装，直接告诉你「这不是游戏 Mod」 |
| 认不出来 | 停下等你手动选目录 |

**自动安装策略**（下载队列）：
- 结构识别成功、**没有覆盖冲突** → 直接装，不用你管；
- **覆盖的是自己上一个版本** → 算升级，照常自动装（会先备份）；
- **会覆盖别的 mod 的文件**，或结构认不出来 → 任务停在「**待确认**」，点「去处理」才装；
- 包里有多套内容 → 弹多选对话框，勾选要装的几套再点「安装选中的（N）」。


手动导入压缩包时会在界面上先给你看安装计划再确认。

**会被覆盖的文件会逐条列出来**（不再只说一句「有 2 个同名文件」）。
确认界面和下载抽屉里都会给出一张清单，每行长这样：

```
Minervha_Master_P.ucas        100743776 → 100743776（一样大）
SB/Content/Paks/~Mods/Minervha_Master_P.ucas
【别的 mod】属于「Academy - CNS」v1.0、「Cammy - CNS」v1.0、「Chun Li Bathing suit - CNS」v1.0 等 4 个

some_P.pak                    1000 → 3333（会被替换）
SB/Content/Paks/~Mods/some_P.pak
【不是 mod 装的】游戏原文件（或手动放进去的）
```

- **一行一颗按钮，点一下就在资源管理器里选中该文件**
- 大小一样 ≈ 同一个文件（CNS 服装常共用同一个底座 pak）；会被真替换的标黄提示
- **排序：最该看清楚的排前面** —— 不是 mod 装的（游戏原文件）→ 别的 mod 装的 → 自己上次装的
- 标成「同一个 mod」的，就是你自己上次装的（升级/重装），不用担心
- ⚠️ 同一路径可能被**多个** mod 登记（CNS 服装共用底座），清单会把它们**全部**列出来 ——
  只报一个会误导

安装是**先解压到临时目录再复制**，中途失败不会污染游戏文件。

**覆盖前会自动备份**：如果目标位置已经有同名文件（CNS 这类框架就会盖掉游戏自己的文件），
程序会先把它备份到 `data/backup/overwritten/ov-<时间戳>/` 再覆盖，
安装完成界面会显示备份了哪些文件。卸载时这些原文件会**自动还原**回原位。

> 备份只针对**游戏原本的文件**。同一个 Mod 装第二次（更新版本）时，程序能分辨出
> 「目标位置这些文件是我上次自己装进去的」，不会把它们当成游戏原文件再备份一遍 ——
> 否则卸载时会把刚移走的文件又还原回来，变成**卸载等于没卸**。
> 重装会复用同一个备份目录，不会每装一次就多留一个 `ov-*`。

装完会登记到本地注册表，可以在「已安装 Mod」里启停或卸载（卸载会先备份到
`data/backup/uninstalled/`，可以手动找回）。

> 解压依赖 **7-Zip**（推荐装在默认路径 `C:\Program Files\7-Zip\`）。
> 没有 7-Zip 时会退回到 Windows 自带的 `tar.exe`。设置页的「解压工具」一行会显示检测结果。

## 安全设计

- **下载授权不落盘**：Nexus 签发的 `key` / `expires` 只存在内存里，任务写进 `data/downloads.json`
  之前会被白名单过滤掉，任何敏感参数都不会留在磁盘上。
- 不抓取 Nexus 网页、不模拟网页点击、不绕过 Cloudflare 人机验证。
- 图片缓存只允许 `nexusmods.com` / `nexus-cdn.com` 及其子域，限单张 12 MB、超时 15 秒，
  拒绝非 `image/*` 响应。
- 卸载不直接删除文件，一律先移到 `data/backup/uninstalled/`，可手动找回。
- 覆盖安装前先备份原文件到 `data/backup/overwritten/`，卸载时自动还原。
- 前置组件默认不提供卸载（删错文件会让游戏起不来）；
  例外是**本程序装的**——注册表里有完整回滚清单 + 覆盖备份，那就是安全可逆的。
- 渲染层关闭 Node 集成，仅通过白名单 IPC 与主进程通信。
